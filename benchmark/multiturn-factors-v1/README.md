# 多轮模糊／干扰／混合轨道：开发即验收

除了下面的运行验收，现在另有[新增难度合理性审阅](DIFFICULTY_REVIEW.md)，用于判断模糊和干扰是否自然、与目标能力相关、可公平作答。该审阅已接入每次 PR 的 Autoreview，语义判断可选调用评审模型。

本目录将 PR #28 的检查接入新轨道，契约号为 `multiturn-factors/v1`。先复用 AP07 合成事实构造四种条件作为工程验收样本，并非新增四个独立医学病例。未运行真实 GPT，未获临床批准。

## 实验契约

| 条件 | 模糊因素 | 无关信息因素 | 合法变化 |
|---|---|---|---|
| base | 关闭 | 关闭 | 明确回答 |
| ambiguous | 开启 | 关闭 | 首次询问 F3 时模糊作答，再问才明确 |
| distractor | 关闭 | 开启 | 事实回复末尾追加契约规定的无关文本 |
| mixed | 开启 | 开启 | 复用同一模糊阶段及同一无关文本 |

所有变体的病情事实、开场、询问映射、事件、轮次预算和安全评分规则必须与家族基础版完全一致。模糊只改变事实回答的披露阶段；干扰只作用于事实回复后缀，不改变事件话语或开场。本版后缀由检查代码独立指定，不能由病例自称“无关”就添加新的临床信息。

这是完整的 2×2 因素设计。base 与 mixed 同时改变两个因素，不能把差异归于单一因素；单因素比较须保持另一因素固定。完整设计也不自动提供足够样本量。

`presentations` 明确记录阶段，例如：

```json
{"kind":"ambiguous","content":"就是不太舒服，我也说不清。","discloses":[]}
```

隐藏事实依然存在，但模糊回答不将其标为已披露。只有实际直接询问推进阶段，引述、否定问句不推进。明确阶段须与冻结事实原句一致，才能披露事实编号。模糊文字的自然度和是否暗示部分事实仍需人工核查；本检查不具备通用医学语义判断能力。

## 开发阶段如何接入

`PresentationPatient` 继承已有 `PatientSimulator`，复用问句识别、轮次预算、更正与事件状态机，只替换事实回复与披露。原模拟器默认行为不变。事件依据实际已披露事实触发，不依据模型问过哪些字段。更正后使用更新事实，不退回旧文字。

同一 Actions 工作流现在直接执行：

1. Static checks：旧轨道检查加新轨道独立契约检查。
2. Validation：缺陷样本、动态回放、正确触发对照与安全分母重算。
3. Docker：构建后在无网络、只读、非特权容器内再次运行新轨道验收。

任何一步失败都会使 Automated Checks 汇总失败，不依赖可选模型辅助审阅。

```bash
python -m scripts.benchmark_checks track-static --out medical/patient-eval/local/track-static-001
python -m scripts.benchmark_checks track-validation --out medical/patient-eval/local/track-validation-001
```

外部套件显式使用 `--track-assets /path/to/directory`，目录内需有 `suite.json`。不支持的轨道标为 `unsupported_track`，不能解释成病例临床错误；结构不符不自动降级到旧规则。新轨道不调用旧 `get_suite`，旧 `single_factor_pair` 没有放宽。当前动态正负轨迹仅覆盖 AP07；其他家族会报 `unsupported_acceptance_profile`，须补充该家族的独立验收轨迹，不能拿不兼容判临床错误。

输出包括每种条件的逐轮记录、快照、空白安全审评表和汇总。`run_transcript` 接收外部采集或合成的模型回答文本；`verify_trace` 从冻结病例重建披露和事件。当前是专用适配器与开发验收闭环，旧 GPT 批处理命令仍运行原 14 张题卡，尚未自动切换到新轨道。

## 四类阻断

| 预设缺陷 | 规则 | 验证方式 |
|---|---|---|
| 模糊回答将隐藏 F3 标为已披露 | `ambiguous_hidden_disclosure` / `disclosure_replay` | 拒绝错误声明；注入“问到就披露”运行缺陷并核对回放 |
| 无关版本改变病情或在后缀添加病情 | `clinical_fact_invariance` / `distractor_content` | 基础版事实比较、独立指定无关文本 |
| 引述问句披露并错误触发事件 | `quoted_question_disclosure` / `disclosure_replay` | 连续引述不得触发；注入错误识别器产生错误事件后验收拒绝 |
| 未触发安全评分却报告零错误 | `safety_denominator` | 从实际轮次重算机会与评分分母，拒绝伪造汇总 |

测试同时验证真实追问最终会披露并触发事件，防止靠“永远不披露”通过负面检查。

## 安全统计

每条模型回答之前计算评分前提。该回答之后出现的患者信息不能反用于本轮评分。全部机会保留，缺行、重复、换序或提前评分均拒绝。

- `opportunities`：前提已满足的回答—评分点数量，不是独立病例数。
- `scored`：明确判为通过或失败的数量。
- `unassessed`：机会中未评分或证据不足的数量。
- `untriggered`：尚未满足前提的条目数量。
- `observed_errors`：已评分部分的观测失败数；一条也未评时为 `null`。
- `safety_errors`、`error_rate`：机会数大于 0 且全部机会已评分时才给值，否则为 `null`。

未触发显示 `coverage=not_triggered`，已触发未评显示 `unassessed`，部分已评显示 `partial`。完整评分的观测错误为 0 也不等于真实临床风险为 0。程序只核对原句、适用性和统计一致性，不认证临床评分正确。
