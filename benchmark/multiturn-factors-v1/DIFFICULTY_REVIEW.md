# 新增难度是否合理：自动审阅说明

目标是判断模糊、无关信息和混合变化有没有形成合理的能力挑战。已有运行验收继续执行，本模块进一步审阅题目设计本身。当前覆盖 AP07 的三个变体与基础版的比较；旧轨道的其他家族尚未纳入这项专项审阅。

## 自动审阅会看什么

| 维度 | 需要回答的问题 |
|---|---|
| 能力对应 | 新增困难究竟考察澄清、筛选、整合，还是只增加文字和机械负担？ |
| 自然度 | 真实患者是否可能这样说？有无不自然的绕口、重复与强迫追问？ |
| 信息可获得性 | 必要信息能否经合法追问获得，是否还留有作答机会？ |
| 评分公平性 | 是否不给信息却强迫确诊？能否接受合理追问、暂缓判断和不确定性？ |
| 变化可控性 | 病情和评分有没有被同时改变？混合条件是否被误当单因素实验？ |

每次提交自动生成：基础版—变体的实际差异、作者声明的目标能力、参考询问路径及其披露结果、文字负担提示，以及仍需语义判断的问题。作者的“很真实”“考察推理”等描述不会被程序直接视作成立。

## 两层检查如何配合

第一层是可计算的设计检查：

- 必要信息没有在环境中提供，作者又明确不允许保留不确定性：报告契约矛盾，自动检查失败。
- 改变病情、事件、预算或评分：报告受控变化问题；既有轨道检查也会阻止不合规入库。
- 提供的参考询问路径未能在作答前取得必要信息：提示补充路径。单条路径失败不证明题目无解，不直接判过难。
- 全部回答阶段的文字量超过基础版 4 倍：提示复核文字负担。这里计的是作者预设的所有回复阶段，不是实测会话长度；4 倍不是经过校准的合格线，不会据此单独判“难度离谱”。

第二层是成对模型辅助审阅：同时给评审模型基础版、完整变体、实际评分、难度说明和机械检查证据，对上述五个维度逐项给出 `reasonable`（合理）、`revise`（需修改）、`excessive`（难度失当）或 `insufficient`（证据不足），并要求原句、位置、原因和具体修改建议。实际评分与作者的合理答案说明冲突时，要以冲突为问题，不能只读作者解释。

输出引用须能在指定版本、指定 JSON 字段逐字核对。缺项、重复规则、伪造引用、请求失败都不能当作审阅通过。模型认为合理也不能覆盖尚未解决的机械问题。该辅助审阅尚未经过独立人工标注集校准，意见供复核，不直接作为临床准入或必需通过的语义分数。

## 怎么使用

每次 PR 的 `Autoreview (rules)` 都自动运行：

```bash
python -m scripts.benchmark_checks difficulty-review --out medical/patient-eval/local/difficulty-001
```

打开 `difficulty-summary.md` 看逐题报告，`difficulty-report.json` 保存完整差异、参考路径、意见与引用。没有调用评审模型时，整体为 `NEEDS_REVIEW`，语义状态为 `NOT_RUN`；工作流执行成功不等于题目难度合理。

如需语义审阅，配置实际可用模型与环境密钥后运行：

```bash
python -m scripts.benchmark_checks difficulty-review --model YOUR_AVAILABLE_MODEL_ID --max-review-calls 10 --out medical/patient-eval/local/difficulty-model-001
```

已有 Actions 的 `model_review` 开关现在同时运行原题目审阅和新增难度审阅。当前原审阅 7 次，新审阅 3 次，共最多 10 次；两个命令各自预算上限默认 10，总调用上限不是共享的。模型输出各次最多 4096 token；按实际账户计费，不自动重试。默认关闭。手动工作流需文件进入默认分支；本次未调用真实模型。

每个变体独立请求，基础版也随请求提供。请求开始和结果即时追加日志，输出目录不允许覆盖；中断后先核对日志，避免重复调用。报告记录规范、题库和难度说明摘要，题库变化导致旧说明过期时必须重新核对，不自动刷新摘要让检查变绿。

`difficulty-plans.json` 的 `rationale` 与 `realism_context` 是作者意图；`required_information` 声明预期回答所需信息，`allows_uncertainty` 和 `acceptable_response` 声明允许的合理边界，`witness_questions` 给出一条可执行取证路径。真实公平性仍须对照病例中的 `safety` 等实际评分规则，由语义审阅核查，不能只修改说明文件掩盖评分缺陷。

## 如何理解例子

“第一次问疼痛程度，患者说不太舒服，再问才明确”是澄清挑战的候选设计；程序可以证明存在这条获取信息的路径，是否自然、是否过于刻意还需要审阅。

“必要检查永远不给，评分又要求明确结论”是需要指出的设计矛盾。信息不足本身可以成为一道好题，但必须容纳识别缺口、继续追问、暂缓判断等合理表现。

“大量无关文字导致失败”不能直接说明医学推理不足。先检查文字负担与目标能力是否一致，再做真实模型对照。

## 实测校准边界

报告的 `empirical_difficulty` 保持 `null`。题目是否让真实模型更难，需要在同模型、同运行条件下比较基础／模糊／干扰／混合版本的完成情况、澄清行为、错误类型和未评分母。不能只靠失败率更高就认定题目更好；应核查模型失败还是模拟器、评分器失败。

本轮测试中的模型响应是接口验证夹具，不是评审模型准确率评测。下一步需要独立人工标注的合理与不合理题卡，衡量漏报、误报和人工分歧，再决定哪些语义意见可成为正式验收要求。
