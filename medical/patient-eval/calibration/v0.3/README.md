# 患者问询识别：v0.3 开发校准

这个目录用于检查“模型问了什么”和“患者应披露什么”之间的映射。它不判断医学答案是否正确，也不负责自动结束问诊。

## 已实现

- 保留 `literal-v0.2` 的原规则，用于明确重放旧采集记录。
- 默认规则 `conservative-zh-v0.3`：识别直接问询和有限的持续时间表达；隔离否定要求、引用、转述、面向医生等第三方的指令；分别处理多问句中的要求。
- 使用更具体的短语抑制嵌套的通用短语。例如“原文日期”不同时披露另一个槽的“日期”；两个槽对同一短语存在完全相同的映射时，保留未映射状态。
- 患者状态保存分类器版本；操作端事件记录保存每句的匹配、抑制原因和人工覆盖。这些证据不进入被测模型的消息。
- 保持未知事实为未知；分类规则不读取事实值、患者答案、评分标准或模型名称。

## 样本和证据边界

[patient-questions.json](patient-questions.json) 含 48 条合成、智能体辅助编写的开发表达，共 6 类：直接问询、口语变体、否定要求、引用或转述、多问句作用范围、非问询或不支持的问询。修改规则前，已逐条记录原分类器输出，保存在 `legacy_observed_slots_before_change`。校准运行会重新执行旧规则，并检查输出与该记录一致。

样本分成 36 条 `development_design` 和 12 条 `development_regression`，**两组均在开发时可见，均不是独立保留集**。标签没有经过独立人工或临床审核。不能把这里的高匹配率写成真实患者语言准确率。

一次本地校准的开发结果：

| 指标 | 原规则 | v0.3 规则 |
|---|---:|---:|
| 披露槽集合完全匹配 | 23 / 48 | 48 / 48 |
| 存在错误披露的表达 | 19 / 48 | 0 / 48 |
| 存在漏披露的表达 | 6 / 48 | 0 / 48 |
| 未映射表达 | 13 | 24 |
| 其中正确保持未映射 | 7 | 24 |

未映射增加并不意味着错误增加：引用、拒绝回答或无支持槽的问题，本就不应触发披露。报告同时给出错误披露槽数、遗漏槽数、各自分母，以及按类型和声明分组的统计。零分母返回空值，不伪造为零错误率。

## 运行

在仓库根目录执行，输出必须是一个尚不存在的文件：

```bash
python -m scripts.patient_eval.calibrate_patient \
  --out medical/patient-eval/local/patient-question-calibration-v03.json

python -m unittest tests.patient_eval.test_patient_intent_v03 -q
```

输出包含样本摘要哈希、两版逐句决策、分组指标和限制说明。样本哈希用于确认比较使用相同输入；它不证明标签独立或正确。结果文件默认放在不提交的本地目录，避免把后续真实语料带入公开仓库。

## 下一次校准需要补什么

1. 请独立标注者编写并标注新的真实口语表达，包含可回答、无需披露及无法确定三类；先冻结表达和标注规范，再运行待测规则。
2. 记录人工覆盖的理由；把分类器漏识别、患者事实缺失和合理结束分别统计。
3. 对接多槽的歧义消解、人物指代、否定作用范围和持续时间时，继续使用原文证据；不要把这套有限规则当成通用中文医学语义分析器。
4. 若开始使用新的分类器版本，须在新会话中记录；旧记录缺版本时只能显式按 `literal-v0.2` 重放，不得伪装成 v0.3 实验。

目前仍是有限模式匹配。未支持的复杂指代、嵌套否定、意图反转和新领域表达需要人工复核；本轮没有引入模型调用、临床安全判据或新的自动停止条件。
