# 专业数据接入包 v0.1

**先补真实中文咨询语言与可靠评分材料，再扩充病历库。** 当前阶段需要可追溯、可复核的小批数据，不能用数据库条数代替测试质量。

核对日期：2026-09-09；项目基线：`fd91e2e9a2c4f72fc7b35975338e1028264391c8`。来源、版本、许可与获取状态见 [registry.json](registry.json)。论文继续放在 `reference/`；本目录管理数据来源和接入证据，不改变已冻结评测套件。

## 1. 我们原先用的是什么

| 现有材料 | 实际规模与用途 | 质量判断 |
|---|---|---|
| 动态患者场景 | 6 家族、12 个合成变体；生成 24 条离线脚本会话 | 适合问询、纠正与压力机制验证；152 个判据尚无人评，没有真实模型成绩 |
| 问询校准表达 | 48 条智能体辅助编写的表达；两组均已暴露 | 适合已知问题回归；48/48 匹配不表示真实口语准确率 |
| 早期受控医学案例 | 12 家族、60 个合成案例 | 有医学背景与受控变量，但 12 家族均需标准答案审核 |
| 案例证据 | 19 条来源记录、43 条主张；其中 12 条外部来源对应 30 主张，7 条合成来源对应 13 主张 | 真实来源有价值；不能把来源核对当成临床标准答案审核 |

现有 43 条主张均带 `source_verified` 标签，其中包含合成来源。该历史标签不应被解释为“43 条真实医学知识已经专家认证”。新数据把**来源类型、文件核对、标注质量、临床审核**分别记录，不回写旧冻结材料。

另外，知识骨架登记了 25 个来源入口，并有药理和特殊人群安全主张；登记入口不等于已下载 25 个数据库。当前主线也没有历史讨论中的 interview-corpus 数据目录，不能把另一分支的面试派生问题算作已接入患者记录。

依据：[现有场景](../../pilot/v0.2/suite.json)、[开发验证](../../VALIDATION_V0.3.md)、[早期案例](../../../case-families/)、[知识来源](../../../knowledge-base/)。

## 2. 引入哪些专业数据

| 优先级与来源 | 用来解决什么 | 必须保留的边界 |
|---|---|---|
| **先接 ReMeDi-base**：Resources for Multi-domain, Multi-service, Medical Dialogues，多领域、多服务医疗对话资源 | 中文真实问法、意图、医学槽位、多轮状态；1,557 条人工细标对话 | 筛选过的在线文本，不代表所有患者；历史医生回复不自动成为标准答案。[作者仓库与许可](https://github.com/yanguojun123/Medical-Dialogue) |
| **随后接 HealthBench**：医疗回答评测集 | 病例评分规则、解释能力、追问与安全标注；5,000 条构建对话、医生编写判据 | 原任务评固定历史后的下一回答；不是完整动态患者。遵守作者不在线披露样例的请求，原文与判据本地保存。[官方说明](https://openai.com/index/healthbench/)、[数据许可](https://github.com/openai/simple-evals/blob/main/README.md) |
| **核清数据许可后接 IMCS-21**：Intelligent Medical Consultation System，智能医疗问诊系统数据 | 4,116 条儿科对话；阳性、阴性、不确定症状与主动问询校准 | 儿科仅 10 类病；缺失不能当阴性；不能由公开文件推定再分发许可。[作者资料](https://github.com/lemuria-wchen/imcs21-cblue)、[原论文](https://arxiv.org/abs/2204.08997) |
| **按组件选 CBLUE**：Chinese Biomedical Language Understanding Evaluation，中文医学语言理解评测 | 实体、关系、诊断标准化和意图识别 | 原版 8 类任务，须逐子集核对许可；组件成绩不等于患者对话能力。[官方项目](https://github.com/CBLUEbenchmark/CBLUE) |
| **后续接 PMC-Patients**：PubMed Central Patients，文献病例摘要资源 | 病情事实、时间线、病例和证据检索；V2 为 250,294 条，原版约 167,000 条 | 文献选择偏差与引用弱标签；署名、非商业、相同方式共享条件；不能提前泄露最终诊断。[作者数据卡](https://huggingface.co/datasets/zhengyun21/PMC-Patients)、[授权说明](https://github.com/zhao-zy15/PMC-Patients) |
| **暂缓 MIMIC-IV-Note**：Medical Information Mart for Intensive Care IV，重症医学信息数据库第四版的临床文书 | 后期病历摘要、否定、时序和报告解释 | 需要身份认证、培训和数据使用协议；不能公开打包或直接交给普通消费者应用。[官方数据与访问条件](https://physionet.org/content/mimic-iv-note/2.2/) |

MedDialog 可作为问法来源，但此次原分发链接、许可及版本未核清，先保留索引，不用镜像替代已核验原版。MedQuAD（Medical Question Answering Dataset，医疗问答数据集）可补英文权威健康资料检索；它的部分回答因来源版权被删除，不能自动补抓，也不是医患会话。[MedDialog 论文](https://aclanthology.org/2020.emnlp-main.743/)、[MedQuAD 官方说明](https://github.com/abachaa/MedQuAD)。

这些用途是 GroundSignal 的接入设计，不能将论文数据的成绩迁移为本项目的成绩。公开数据可能被当前模型用于预训练；上游名为 test 的分区也不等于模型没见过。

## 3. 本轮接入方式

首个实现只支持固定版本 ReMeDi-base。执行下载、文件身份校验、真实格式解析、聚合质量检查和确定性候选抽样；不生成诊疗标准答案，也不把原始对话强制改成交替问答。

```bash
python -m scripts.patient_eval.source_intake \
  --out medical/patient-eval/local/source-intake/remedi-run-01
```

只访问作者公开的固定提交，保留原许可与文件内容。输出目录须不存在；原文和候选编号留在已忽略的本地目录。公共仓库保留下载脚本、版本、文件摘要、许可证来源与[不含原文的聚合审计](remedi-base-audit.json)。全库获取是为了校验与抽样，不代表全库已经变成测试集。

文件核对采用 Git 文件对象摘要，并计算 SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列，用于确认下载字节一致）；散列一致不能证明标签或医学回答正确。原始标注覆盖率也不能当作标注准确率。

本轮已实际下载核对完整人工集，约 16.6 MB，结果如下：

| 实物审计项 | 数量与解释 |
|---|---|
| 原始对话／话轮 | 1,557／36,291 |
| 空白话轮 | 3；保留原文件，相关记录暂不作为可用候选 |
| 规范化后重复对话 | 20；仅在结构可用对话中，按角色与全文序列去重，尚未检查近重复和同文异标 |
| 结构可用且去重后对话 | 1,535；只代表能读取和抽样，尚未核定医学有效性 |
| 含连续同角色发言 | 1,518 段；这是描述性特征，不是错误，不能强制套入交替会话格式 |
| 非空动作标注的话轮 | 36,145；只核对容器和存在性，未验证语义标签准确率 |
| 待审阅候选 | 50；编号仅在本地清单，不代表已生成 50 条可用测试题 |

还有一个实际适配问题：作者文档写 `dialogue_id / turn_id / semantical_labels`，固定文件实际使用 `dialogue / turn / actions`。接入器依据实物解析，保留原始顺序，避免“下载成功但字段没有正确读入”。目前残余身份信息与医学标签均未独立复核。

## 4. 从来源材料变成测试题，要经过什么

1. **先审来源和残余身份信息。** 检查许可、完整原文、人物角色、空文本和缺失；检测手机号、地址、姓名等残留，并人工复核。作者声明匿名不替代本地检查。不能为脱敏而删掉病程、年龄区间、否定词和关键时间关系。
2. **提取事实与不确定性。** 为疾病、症状、药名、时间、经历者记录原文位置；区分“有、无、未知、冲突”。原对话没有问到的信息保持未知，不从最终诊断倒推早期事实。
3. **按来源分组，再做派生。** 相同对话、同一患者或文献及其改写放在同组。先规范化和精确去重，后续再审近重复；不能把相邻话轮随机分进训练与测试两边。
4. **构建患者事实卡与披露脚本。** 初始主诉、可追问事实、后续纠正和评分参考分开；补写的内容标为人工或合成派生。已存在完整文本不代表可以直接模拟任意追问。
5. **独立制定和审核判据。** 医学专家判断可接受行为、严重错误与正当停止；两名评分者独立标注机会、质量与安全。历史医生回复只是参考，不能用字面相似度直接判模型对错。
6. **再进入执行与对照。** 先做固定历史回答，再做经审核的动态患者。公开来源构成开发或外部复现组；正式独立评测继续执行 S5（第五阶段：案例准入）原流程。

评分所需答案与未来事实不能加入被测模型的检索库；知识检索语料、抽取校准语料、评分器校准材料和最终评测病例分别登记。

## 5. 算法和工程的下一批任务

| 任务 | 算法用途 | 工程交付与判定 |
|---|---|---|
| 真实问法校准 | 意图分类、否定范围、人物与时间抽取 | 原文到槽位的逐项证据；误披露、漏披露、无法判定与人工覆盖分别统计 |
| 去重与覆盖 | 文本规范化、近重复聚类、分层抽样 | 同源组标识、跨分区重叠报告；病种覆盖和语言现象覆盖分开，不把条数当代表性 |
| 患者脚本派生 | 有限状态机与事件顺序控制 | 可见前缀、隐含事实、允许披露及修订记录；同事实与改变事实的压力测试分开 |
| 评分校准 | 分项混淆矩阵、评分者一致性与严重错误漏检 | 保留初始标签、裁决和版本；临床未审项不放行 |

建议先审阅本轮抽出的至多 50 个对话候选，确定其中适合的原始病例；再针对澄清、否定、纠正与患者复述建设首批小规模开发案例。该抽样是可复现的审阅起点，不是临床代表性抽样；病种标签、独立人工审核与实际模型结果尚未补齐。
