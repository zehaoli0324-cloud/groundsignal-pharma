# 合成统计与数据查询练习 v0.1

这份练习解决一个常见问题：同一张结果表里混着病例、会话、重复运行、评分机会和评审记录时，很容易把分母算错。它只含合成元数据，不含患者原文，也不产生模型质量结论。

## 术语表

- SQL（Structured Query Language，结构化查询语言）：从表格型数据中筛选、关联和汇总记录。
- SQLite（轻量单文件数据库）：无需部署数据库服务，整个练习数据库保存在一个本地文件中。
- Cohen's kappa（科恩一致性系数）：衡量两名评审超出随机一致的评分一致程度。本项目使用0、1、2分的线性加权版本；一致不等于正确。

## 先手算，再运行

输入是 `statistics-fixture-v0.1.json`。建议李泽豪先遮住下表，用纸笔独立计算，再与程序结果核对；助手生成的答案不能计为本人独立掌握。

| 要数的对象 | 手算结果 | 为什么 |
| --- | ---: | --- |
| 独立病例 | 3 | case-a、case-b、case-c |
| 会话 | 7 | 每个流程分支和重复执行都是一条会话 |
| 重复会话 | 1 | case-a 的 baseline 在同一平台除首次外多运行1次 |
| 完成会话 | 5 | 状态明确为 completed |
| 目标接口失败 | 1 | transport_error；保留在服务完成率分母 |
| 测量无效 | 1 | collector错误；单列，不能算模型成功或失败 |
| 服务完成率 | 5/6≈83.3% | 5 ÷（5完成 + 1目标失败） |
| 计划评分机会 | 7 | 每条合成会话各1条 |
| 已到达机会 | 3 | recorded_status=occurred |
| 未到达 / 未评 / 不适用 | 1 / 2 / 1 | 三类不能填成零分或正确 |
| 至少一人给出质量分的机会 | 3 | 两人评分记录的并集 |
| 两人都给出质量分的机会 | 1 | 只有 case-a:baseline:r0:correction |
| 两位评审都没有记录的机会 | 1 | 仅看评分表会漏掉，需与机会表关联才能发现 |

“7条会话”不能写成“7个病例”；同一病例的重复运行也不是新独立样本。以后做置信区间时，应按独立病例或来源组处理，不能把相关话轮当成独立样本。

## 三条查询分别回答什么

1. **病例完成情况**：逐病例列出会话、重复运行、完成、目标失败、测量无效及有效目标分母；尚未运行的病例也保留为0，不从表中消失。
2. **错误类别分布**：目标接口失败与采集器导致的测量无效分开。前者是系统没有完成任务，后者表示我们没有获得有效测量。
3. **两人都实际评分的条目**：只有两位指定评审的 `quality_status` 都是 `assessed` 且0/1/2分不为空，才进入结果。

可读SQL保存在 `statistics-queries-v0.1.sql`；运行代码复用现有 `agreement.py` 的一致性计算，没有重写另一套科恩一致性系数。

## 运行

在仓库根目录执行：

```bash
python -m scripts.patient_eval.readiness_statistics \
  --input medical/patient-eval/readiness/statistics-fixture-v0.1.json \
  --db medical/patient-eval/local/statistics-practice.sqlite \
  --report medical/patient-eval/local/statistics-practice-report.json
```

本地数据库和练习报告位于已忽略目录，不上传。输入文件、数据库文件和报告文件都不允许静默覆盖；换文件名可保留首次失败。公开的首次聚合结果是 `round-4-statistics-report.json`。

## 怎样解释一致性结果

合成表中只有1条机会由两人都完成0/1/2分评分，两人的分数为1和2，因此程序可算出加权科恩一致性系数为0。但样本只有1条，这个数没有稳定统计意义，更不能证明谁的评分符合医学事实。

现有一致性函数只看至少一位评审出现过的条目，因此其输入并集是6条；机会表显示实际预期是7条，额外发现1条被双方同时漏评。统计系统必须同时保存“应该评什么”和“实际交回了什么”，否则覆盖率会被高估。

本练习没有独立评审者：`synthetic-A/B` 都是作者构造标签。它验证的是数据关系、分母和查询，不是双人独立验收，也不证明李泽豪已能独立解释这些指标。
