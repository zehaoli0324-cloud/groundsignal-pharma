# T02：自动记录预选、改选和确认

使用 [默认勾选版0.2.2](../console-v0.2.2-interaction-records.html)。不增加审阅步骤：符合默认答案时点确认，有问题时改选后确认，可随时保存。四个默认答案保持为“原文支持这条信息。”“未发现患者身份信息”“适合考察，具体评分标准待补充”“足够理解本段情况。”

## 为什么区分这些记录

| 实际操作 | 答案状态 | 程序记录 |
| --- | --- | --- |
| 只进入题目，未操作 | 未答 | 最近一次页面展示了预选；没有确认记录 |
| 直接确认默认项 | 已选、已确认 | 沿用预选确认 |
| 改选但还未确认 | 已选、未确认 | 主动选择；不能算点击过确认 |
| 改选后确认 | 已选、已确认 | 主动选择后确认；即使改回默认项，也按此记录 |
| 已确认后再改选 | 已选、未确认 | 清除对旧答案的确认，等待新确认 |
| 暂时跳过 | 未答 | 清除当前选择与确认；保留原始导入来源 |
| 恢复旧答卷 | 保留原答案 | 旧版界面与确认方式未知，不按答案是否等于默认值猜测 |
| 在新版重新确认旧答案 | 已选、已确认 | 记录“重新确认旧答案”；原始版本的确认历史仍未知 |

展示记录只表示程序在点选模式呈现了该题，不证明人看过或理解了原文。统计不宣称评审耗时下降、准确率提高或预选没有偏差。页面顶部的已选与已确认分别计数。

## 格式与兼容性

界面版本为0.2.2；点选答卷格式升级为 `clinical-console-choice-bundle/v0.3`，其答案版本为 `clinical-console-choices/v0.3`。这些是文件版本标识，不是模型分数。

新答案增加 `interaction`，其内部版本为 `clinical-console-interaction/v0.1`。每条记录按病例、板块和题目编号绑定，完整覆盖所有题目；缺项、重排、额外字段或矛盾的确认被拒绝。

| 字段 | 含义 |
| --- | --- |
| `export_ui_version` | 导出使用的界面版本 |
| `origin_answers_version` | 此份答卷在记录系统中的起始版本 |
| `origin` | 初始版本、初始答案和已知的起始界面版本；旧v0.2的界面版本为 `null`，表示未知 |
| `display` | 最近一次呈现的界面版本、是否展示未答题预选及显示答案；没有记录时为 `null` |
| `selection` | 最近一次主动改选；没有主动改选或跳过后为 `null` |
| `confirmation` | 当前答案的确认方式、答案、当时界面版本和当时是否展示预选；未确认或改选后为 `null` |
| `last_action` | 未呈现、已呈现、已选择、已确认、已跳过或旧历史未知 |

这是当前状态记录，不是完整点击日志。再次呈现会更新 `display`；重复确认同一个答案保留有效的原确认。主动改选和跳过清除旧确认。没有身份签名、可信时间戳或第三方存证，不能仅凭这些字段证明人类行为真实。

兼容规则：

- 旧v0.2仍可由原验证入口核验。前端恢复时复制并升级，原文件和原答案不被覆盖；旧数据缺失不补成肯定值。
- 新版原始答卷必须保留。转换到原候选审阅格式时，操作记录不塞入旧格式，单独在验证报告输出摘要。
- 原有 `answered` 仍表示已选答案数；新增摘要明确列出预选确认、改选确认、旧答案重新确认、改选未确认与旧确认未知，不能混用分母。
- 新旧版本比较仍比较答案与缺失项，不把操作方式不同解释成医学意见分歧。
- 事实准入、临床资质、独立性和评分标准不会因为记录了确认而自动通过。

## 合成验证与他人验收

已有19项测试首先通过。新增7项后共26项通过，包括10组前端状态检查及11种矛盾记录的前后端拒绝。没有执行真实病例或模型调用，也没有进行浏览器点击、下载或视觉验收。

```bash
python -m unittest tests.patient_eval.test_clinical_console_interactions tests.patient_eval.test_clinical_console_choices tests.patient_eval.test_clinical_console -v
```

协调者可沿用 `clinical_console validate-choices` 与 `compare-choices` 命令。新旧答卷都受来源和不可变内容校验。报告摘要见 [round-6-interaction-report.json](round-6-interaction-report.json)，首次测试输出见 [round-6-verification.txt](round-6-verification.txt)。

下一位实际使用者只需体验合成示例：确认一题、改选一题并确认、跳过一题，保存后关闭并重新打开，选择同一评审席位恢复答卷。核对选项和已确认数量是否保持，再交回文件及问题。请李泽豪处理反馈并留记录；助手自测不能代替这项验收。

预选是否影响判断质量仍需另行组织小规模人工比较，本轮没有完成这项研究。
