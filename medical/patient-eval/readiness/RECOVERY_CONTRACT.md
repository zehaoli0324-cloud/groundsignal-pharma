# 合成运行恢复合同 v0.1

本轮实现的是**只读恢复前检查**，不是续跑执行器。它复用原运行器的配置构造、调度与会话校验，只接受合成开发病例；不调用模型、不改检查点、不重试会话。

## 运行与预期

需要 Python 3.11或更新版本，无第三方依赖。在仓库根目录执行：

```bash
python -m scripts.patient_eval.recovery --drill-out medical/patient-eval/local/recovery-first
python -m unittest tests.patient_eval.test_recovery_preflight -v
```

演练只生成固定合成输入并故意中断本地脚本响应。预期保存1条、待执行1条；`consistency_passed=true` 表示已检查字段内部一致，`resume_allowed=false` 表示仍不能续跑。15项新测试覆盖负向与边界情况。已有目录会被拒绝，请保留首次结果，换新名称；不要清空后冒充首次成功。

供代码复用的入口为 `inspect_recovery(suite, client_config, out, repeats=1, seed=7)`。其中第二参数是公开配置字典，不是客户端，因此检查函数没有调用模型的入口。

## 本轮检查和处置

| 情况 | 检查或处理 |
| --- | --- |
| 输入、配置、策略/抽取器/分类器版本、重复次数、种子、调度顺序变化 | 与期望输入及现运行器配置逐项比较，不一致即报告拒绝原因 |
| 会话缺失、计数错误、身份或来源字段变化 | 核对连续编号、会话合同、场景、配置、响应状态与摘要清单 |
| 清单引用目录外路径或符号链接 | 拒绝；不会跟随清单指定的任意路径读取 |
| 已落盘但清单未登记的会话 | 视为孤立文件，拒绝自动接纳；保留原文件 |
| 未落盘结果、残留临时文件、意外汇总文件 | 不猜测是否完成、不删除、不重新执行；报告目录不一致 |
| 已完成运行 | 核对汇总和单会话一致性，待执行数为0，明确不重跑 |
| 已保存超时等失败会话 | 算作已保存记录，不算成功结果；不删除或自动重试 |
| 清单仍写“运行中” | 进程存活状态为未知，不能直接判断仍活着或已死亡 |

检查得到的文件摘要只是**本次观察值**，不是历史可信摘要。测试专门修改一段仍满足格式的合成回答：其内部一致性检查可以通过，但结果仍标记完整性未获证实、续跑不允许。不能把这个限制藏在“全部检查通过”背后。

当前没有排他锁。只读结果不保证与并发写入隔离，也不提供针对恶意文件替换的安全隔离。因此它只用于受控本地合成目录诊断，不能作为执行授权。

## 下一实现的验收合同（尚未实现）

1. 新运行显式声明可恢复格式，执行前记录输入、配置、调度与代码版本；旧v0.2格式不静默迁移为可信恢复源。
2. 每个已保存会话在清单中绑定字节摘要，校验所有已完成会话后才允许跳过。摘要用于本地意外损坏检测，不能让病例或清单自证临床可信。
3. 排他运行锁必须覆盖检查和写入；未持锁时不得写入。锁和存活状态不能仅凭旧时间戳推定；异常退出和强制终止分别说明处置方式。
4. 显式恢复保持已完成会话字节不变，新增调用只属于未完成会话；失败会话保留在原分母，不自动洗掉。
5. 未落盘的进行中会话可能已发生调用：不得承诺“恰好一次”。若以后允许重放，应明确记录重复风险与新尝试；当前仍只演练本地脚本。
6. 孤立会话、临时文件、摘要不匹配均在新增调用前拒绝，保留首个失败目录；不能通过删除异常文件自动解锁。
7. 只捕获可处理的中断并记录为中断，不把这一机制称为强制终止后也能可靠更新清单。

本轮不改变真实来源准入、S5冻结证据或S6状态。用户的四项默认勾选原文件未修改。本人独立学习、另一人复现和双人评分仍待人工验收。
