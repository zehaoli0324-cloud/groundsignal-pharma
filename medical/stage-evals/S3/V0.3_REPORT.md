## 术语表

- **ClaimFrame（结论框架）**：将医学结论表示为主体、关系、客体、条件、动作强度、因果状态和时间状态等结构字段。
- **Frame extractor（框架抽取器）**：把自然语言证据或候选结论转换成 ClaimFrame 的组件。
- **Shadow held-out（影子留出集）**：在 verifier 实现完成后才冻结、首次运行前未用于修改 verifier 的测试集。
- **False support（错误支持）**：证据不支持甚至反驳结论，但 verifier 判为 `DIRECT_SUPPORT（直接支持）`。
- **Polarity（极性）**：关系是肯定、否定还是未知，例如“提供禁忌规则”与“没有提供禁忌规则”。
- **Atomic proposition（原子命题）**：只表达一个核心关系/动作/条件的最小语义单位。
- **eGFR = estimated Glomerular Filtration Rate（估算肾小球滤过率）**。
- **CYP3A = Cytochrome P450 3A（细胞色素 P450 3A 酶系）**。
- **PK = Pharmacokinetics（药代动力学）**。
- **PGx = Pharmacogenomics（药物基因组学）**。

# 1. Why v0.3 was built

S3 v0.2 showed that unordered semantic cues were not enough. In particular, the verifier could see the word `supersedes` without preserving who superseded whom, and it could detect association/causality words without preserving causal polarity.

v0.3 therefore introduced a directional ClaimFrame contract:

```text
subject
predicate
object
polarity
condition
modality
causal_status
temporal_status
limitations
```

The intended improvement was to make relations directional rather than treating them as a bag of semantic labels.

# 4. Critical false-support failures

## 4.1 eGFR range/action binding

Evidence:

```text
new treatment:
eGFR 30–45 → initiation not recommended

eGFR <30 → contraindicated
```

Candidate:

```text
eGFR 34 meets the contraindication criterion
```

Gold:

```text
CONTRADICTS
```

Prediction:

```text
DIRECT_SUPPORT
```

Root cause:

The numeric parser used a broad local text window. Because two separate actions occurred in the same compound sentence, the `<30 contraindicated` action was incorrectly attached to the `30–45` range.

Failure family:

```text
CLAUSE_ACTION_BINDING_ERROR
THRESHOLD_ERROR
```

# 5. The architectural diagnosis

The important conclusion is:

> **Directional ClaimFrame is a necessary representation, but the v0.3 extractor is still unsafe because it builds frames from whole compound sentences rather than clause-scoped atomic propositions.**

The current pipeline:

```text
compound sentence
→ broad-window feature extraction
→ one merged frame
→ frame comparison
```

causes three structural problems.

## Problem A — wrong condition/action attachment

```text
condition A + action A ; condition B + action B
```

can become:

```text
condition A + {action A, action B}
condition B + {action A, action B}
```

This is unacceptable for threshold-sensitive medication rules.

## Problem B — negation becomes a positive feature

```text
"does not provide a contraindication rule"
```

must become:

```text
predicate = PROVIDES_CONTRAINDICATION_RULE
polarity = NEGATIVE
```

It must never become a positive `CONTRAINDICATED` modality merely because the word appears.

## Problem C — positive lexical/frame-overlap fallback is unsafe

When structured fields are unresolved, high overlap currently can still return `DIRECT_SUPPORT`.

For medical high-risk claims this is the wrong default.

The safer rule is:

```text
unresolved structural mismatch
→ DOES_NOT_SUPPORT or HUMAN_REVIEW

never
→ DIRECT_SUPPORT
```

# 6. v0.4 design requirement

S3 v0.4 should introduce:

```text
Evidence passage
        ↓
Clause segmentation
        ↓
Atomic proposition extraction
        ↓
Polarity-preserving proposition frames
        ↓
Candidate claim proposition frames
        ↓
Constraint / fieldwise comparison
        ↓
DIRECT_SUPPORT / PARTIAL_SUPPORT / CONTRADICTS / DOES_NOT_SUPPORT
```

Example evidence should become two separate propositions:

```json
{
  "subject": "metformin_initiation",
  "predicate": "NOT_RECOMMENDED",
  "condition": {"variable": "eGFR", "operator": "RANGE", "low": 30, "high": 45},
  "polarity": "POSITIVE"
}
```

and:

```json
{
  "subject": "metformin_use",
  "predicate": "CONTRAINDICATED",
  "condition": {"variable": "eGFR", "operator": "LT", "value": 30},
  "polarity": "POSITIVE"
}
```

Negated evidence must be explicit:

```json
{
  "subject": "mechanism_evidence",
  "predicate": "PROVIDES_CONTRAINDICATION_RULE",
  "object": "drug_pair",
  "polarity": "NEGATIVE"
}
```

Causality limitation:

```json
{
  "subject": "observational_analysis",
  "predicate": "ESTABLISHES_CAUSALITY",
  "object": "A_causes_B",
  "polarity": "NEGATIVE"
}
```

Temporal supersession:

```json
{
  "subject": "Guideline_C",
  "predicate": "SUPERSEDES",
  "object": "Guideline_B",
  "polarity": "POSITIVE"
}
```
