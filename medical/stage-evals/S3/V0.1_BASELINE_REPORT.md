# S3 v0.1 Baseline Report

> **S3 = Stage 3, Evidence Verification & Temporal Truth（证据验证与时间真值）**  
> Baseline verifier: `s3-naive-lexical-v0.1.0`  
> Status: **FAIL — unsafe for downstream truth construction**

## 术语表

- **Verifier（证据验证器）**：判断一条证据是否真的支持候选医学结论的组件。
- **DIRECT_SUPPORT（直接支持）**：证据直接支持候选结论。
- **PARTIAL_SUPPORT（部分支持）**：证据只覆盖候选结论的一部分。
- **CONTRADICTS（矛盾）**：证据与候选结论直接冲突。
- **DOES_NOT_SUPPORT（不支持）**：证据不足以支持候选结论。
- **Scope（适用范围）**：结论在什么患者、条件、时间、剂量或使用状态下成立。
- **Threshold（阈值）**：例如 eGFR <30 这种会改变规则适用性的数值边界。
- **False support（错误支持）**：本来不应被证据支持的结论，被 verifier 错判成 `DIRECT_SUPPORT`。
- **eGFR = estimated Glomerular Filtration Rate（估算肾小球滤过率）**：临床常用的肾功能指标。

---

# 1. Baseline design

The first S3 verifier intentionally used a simple and transparent approach:

```text
Evidence text
+ Candidate claim
        ↓
lexical token overlap
+ a small number of generic safety guards
        ↓
DIRECT / PARTIAL / CONTRADICTS / DOES_NOT_SUPPORT
```

The purpose was not to build the final verifier. The purpose was to establish a lower-bound baseline and test whether the stage eval can expose unsafe evidence interpretation.

---

# 2. First-run result

```text
n_items                         24
relation_accuracy               58.3%
high_risk_negative_items        12
high_risk_false_support_count   1
high_risk_false_support_rate    8.3%
release_gate                    FAIL
```

Confusion summary:

```text
DIRECT_SUPPORT → DIRECT_SUPPORT        3
DIRECT_SUPPORT → PARTIAL_SUPPORT       5
DIRECT_SUPPORT → DOES_NOT_SUPPORT      4
CONTRADICTS    → CONTRADICTS           5
CONTRADICTS    → DIRECT_SUPPORT        1
DOES_NOT_SUPPORT → DOES_NOT_SUPPORT    6
```

The most important failure is not the low average accuracy. It is the one **high-risk false support**.

---

# 3. Critical failure: metformin scope expansion

Evidence proposition:

```text
For an existing metformin user:
- eGFR <45 → reassess benefit/risk
- eGFR <30 → discontinue
```

Candidate claim:

```text
Every patient already taking metformin must discontinue it as soon as eGFR falls below 45.
```

Gold relation:

```text
CONTRADICTS
```

Naive verifier prediction:

```text
DIRECT_SUPPORT
```

Why it failed:

```text
lexical overlap = high
metformin ✓
eGFR ✓
below 45 ✓
existing treatment ✓

but action modality was different:
reassess benefit/risk ≠ discontinue
```

Failure class:

```text
SCOPE_EXPANSION
+ ACTION_MODALITY_MISMATCH
```

This is medically important because a text-similarity verifier can treat a dangerous management escalation as evidence-grounded simply because most words match.

---

# 4. Other observed failure patterns

The baseline also under-recognized valid support when the claim was semantically equivalent but phrased differently.

Examples:

```text
metformin eGFR 35 initiation not recommended
→ predicted PARTIAL instead of DIRECT

apixaban + NSAID increases bleeding risk
→ predicted PARTIAL instead of DIRECT

ClinicalTrials.gov record says study status COMPLETED
→ predicted DOES_NOT_SUPPORT despite direct registry support

CYP3A inhibitor + CYP3A substrate
→ potential pharmacokinetic interaction mechanism
→ predicted DOES_NOT_SUPPORT
```

These are mostly false negatives rather than dangerous false positives, but they show that pure token overlap is not an adequate entailment model.

---

# 5. Engineering conclusion

Do **not** fix this baseline by adding case-specific phrases such as:

```text
if "below 45" and "discontinue": CONTRADICTS
```

That would overfit the current 24 items.

The next verifier must explicitly compare structured semantic fields:

```text
subject / entity
population or use state
action modality
numeric threshold or range
risk vs diagnosis
mechanism vs clinical management
causality level
temporal status
negation / exception
```

For example:

```text
Evidence:
condition = eGFR <45
action = reassess benefit/risk
use_state = existing_user

Claim:
condition = eGFR <45
action = discontinue
use_state = existing_user

→ action mismatch
→ CONTRADICTS
```

This is the core design requirement for S3 v0.2.

---

# 6. Release rule

S3 should not feed automatic gold claims into the Knowledge Graph while:

```text
High-risk False-Support Rate > 0
```

The v0.1 baseline is therefore frozen as a failed lower bound and should remain reproducible in Continuous Integration regression history.
