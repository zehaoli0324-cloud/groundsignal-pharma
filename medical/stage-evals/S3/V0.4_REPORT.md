## 术语表

- **Atomic Proposition（原子命题）**：只表达一个关系、动作、条件或限制的最小语义单位。
- **Compositional Entailment（组合式蕴含）**：先分别判断候选结论中每个原子命题是否被证据支持，再把多个子判断组合成整个结论的最终关系。
- **DIRECT_SUPPORT（直接支持）**：候选结论的必要内容均被证据支持，且没有未被支持的重要扩展。
- **PARTIAL_SUPPORT（部分支持）**：候选结论中至少一部分被支持，但还包含未被证据支持、被限制或被反驳的额外内容。
- **CONTRADICTS（矛盾）**：证据明确否定候选结论中的核心主张。
- **DOES_NOT_SUPPORT（不支持）**：证据没有足够信息支持候选结论。
- **False Support（错误支持）**：本不应得到 `DIRECT_SUPPORT` 的结论被错误提升为直接支持。
- **eGFR = estimated Glomerular Filtration Rate（估算肾小球滤过率）**：常见肾功能指标。
- **PGx = Pharmacogenomics（药物基因组学）**：研究遗传差异与药物暴露、疗效或安全性的关系。
- **CYP3A = Cytochrome P450 3A（细胞色素 P450 3A 酶系）**：常见药物代谢酶系统。

# 1. Why v0.4 was built

v0.3 proved that a directional schema alone is not enough when a compound sentence is parsed as one large semantic bag.

The main v0.3 failure pattern was:

```text
condition A + action A ; condition B + action B
        ↓ broad-window extraction
condition A + {action A, action B}
condition B + {action A, action B}
```

v0.4 therefore changed the architecture to:

```text
Evidence passage
→ clause segmentation
→ atomic proposition extraction
→ polarity-preserving proposition frames
→ candidate proposition extraction
→ proposition comparison
```

The design intentionally removed permissive lexical-overlap fallback from the primary safety path.

---

# 2. Development regressions before creating a new held-out

The initial `v0.4.0` atomic parser was first tested only on the already-exposed v0.1/v0.2/v0.3 diagnostic suites.

Those tests found remaining generic parser gaps such as:

- `between eGFR 30 and 45` range syntax;
- additional causal-negation paraphrases;
- incidence-negation paraphrases;
- bounded safety-signal language;
- PGx exposure-association vs dose-management language.

Rather than spending a new untouched held-out on bugs already detectable in historical suites, those parser issues were addressed in `v0.4.1`.

`v0.4.1` development diagnostic results were:

```text
v0.1 diagnostic: 95.8% accuracy, high-risk false support 0
v0.2 diagnostic: 100%  accuracy, high-risk false support 0
v0.3 diagnostic: 100%  accuracy, high-risk false support 0
```

These results were **development regressions only**. They were not treated as new generalization evidence.

The new set deliberately added **PARTIAL_SUPPORT** cases, because real medical answers are often mixed:

```text

```

- bleeding risk is supported, but “elderly patients have the highest risk” is unsupported;

- PGx exposure association is supported, but universal dose reduction is unsupported;
- an imaging report supports “indeterminate + MRI follow-up”, but not “probably malignant”.

# 5. The most important new finding: composition, not only parsing

v0.4 substantially reduced the original condition/action leakage problem on old diagnostics. The new held-out exposed a different architectural limitation:

> **The verifier can correctly support one subclaim and still return `DIRECT_SUPPORT` before evaluating a second unsupported or dangerous subclaim.**

That means the verifier still behaves too much like:

```text
find one supported proposition
→ return DIRECT_SUPPORT
```

when it should behave like:

```text
split candidate into all atomic propositions
→ judge each proposition independently
→ aggregate all proposition verdicts
→ final whole-claim relation
```

This is the central v0.4 result.

# 6. Critical first-run failures

## 6.1 Observational association → causal claim

Item: `S3V4-025`

Evidence:

```text
cohort study found an association between P and Q;
study design is insufficient to establish a causal effect
```

Candidate:

```text
cohort establishes that P causally produces Q
```

Gold:

```text
CONTRADICTS
```

Prediction:

```text
DIRECT_SUPPORT
```

This is one of the two high-risk false supports.

Root cause:

The parser did not normalize the new phrase:

```text
insufficient to establish a causal effect
```

into the explicit negative proposition:

```text
ESTABLISHES_CAUSALITY = NEGATIVE
```

The candidate's association-related proposition was recognized, and the verifier then treated the recognized subset as sufficient for direct support.

Failure family:

```text
CAUSAL_NEGATION_PARAPHRASE_GAP
+
COMPOSITION_EARLY_RETURN
```

---

## 6.2 Imaging: supported report facts + unsupported malignancy extension

Item: `S3V4-030`

Evidence:

```text
lesion is indeterminate
MRI is recommended
malignancy is not established
```

Candidate:

```text
lesion is indeterminate
MRI is recommended
but lesion is probably malignant
```

Gold:

```text
PARTIAL_SUPPORT
```

Prediction:

```text
DIRECT_SUPPORT
```

This is the second high-risk false support.

The verifier correctly recognized:

```text
indeterminate ✓
MRI follow-up ✓
```

but returned `DIRECT_SUPPORT` before fully accounting for:

```text
probably malignant ✗
```

Failure family:

```text
COMPOSITION_EARLY_RETURN
+
UNSUPPORTED_DIAGNOSTIC_EXTENSION
```

This is the clearest evidence that final classification must be an aggregation over **all** candidate propositions.

# 7. PARTIAL_SUPPORT is now a first-class requirement

The v0.4 set intentionally introduced mixed claims. Several failures show that a binary “some support vs no support” verifier is insufficient.

### Example A — trial registry

Evidence supports:

```text
study completed ✓
primary endpoint identity ✓
```

but does not support:

```text
endpoint successfully achieved ✗
```

Candidate combines both.

Gold:

```text
PARTIAL_SUPPORT
```

Observed:

```text
DIRECT_SUPPORT
```

because the registry-specific shortcut returned after the supported registry facts.

### Example B — PGx

Evidence supports:

```text
genotype associated with increased exposure ✓
```

but explicitly provides no dose recommendation.

Candidate combines:

```text
exposure association ✓
+
universal lower-dose requirement ✗
```

Gold:

```text
PARTIAL_SUPPORT
```

The current verifier is too conservative or too aggressive depending on which shortcut fires.

# 8. Other generalization gaps

The untouched set also exposed several paraphrase/ontology gaps that should be fixed generically rather than item-by-item:

```text
"raises the bleeding risk"
→ INCREASES_RISK

"insufficient to warrant causal attribution"
→ ESTABLISHES_CAUSALITY = NEGATIVE

"does not determine the true event frequency"
→ ESTIMATES_TRUE_INCIDENCE = NEGATIVE

"leaves the dosing decision unresolved"
→ PROVIDES_MANAGEMENT_RULE = NEGATIVE

"no randomized head-to-head superiority test"
→ PROVES_SUPERIORITY = NEGATIVE
```

These are parser coverage problems, but they are secondary to the composition problem.

# 9. v0.5 architecture: Compositional Proposition Entailment

The next verifier should not directly classify the whole claim from one shortcut.

Required pipeline:

```text
Candidate claim
        ↓
atomic propositions P1, P2, ... Pn
        ↓
for each proposition independently:
SUPPORTED / CONTRADICTED / UNSUPPORTED
        ↓
aggregate proposition verdicts
        ↓
whole-claim relation
```

Recommended aggregation:

```text
all propositions SUPPORTED
→ DIRECT_SUPPORT

at least one SUPPORTED
+ at least one UNSUPPORTED or CONTRADICTED
→ PARTIAL_SUPPORT

no SUPPORTED
+ at least one CONTRADICTED
→ CONTRADICTS

no SUPPORTED
+ no CONTRADICTED
→ DOES_NOT_SUPPORT
```

For high-risk medical claims, one additional hard rule applies:

```text
if any dangerous causal / diagnostic / management / dose proposition
is UNSUPPORTED or CONTRADICTED

whole claim can NEVER be DIRECT_SUPPORT
```

This removes early-return shortcuts from the safety path.

# 11. Next experiment

S3 v0.5 should:

1. preserve the v0.4.1 parser as the starting extraction layer;
2. add missing generic negative propositions for causality, incidence, management and superiority;
3. independently classify every candidate atomic proposition;
4. remove whole-claim early-return shortcuts;
5. aggregate proposition verdicts into `DIRECT / PARTIAL / CONTRADICTS / DOES_NOT_SUPPORT`;
6. rerun v0.1–v0.4 only as diagnostics;
7. freeze a new untouched v0.5 shadow-heldout **after implementation**;
8. require:

```text
Relation Accuracy >= 80%
High-risk False-Support Rate = 0
```

before S3 can be considered for `READY_FOR_KG_TRUTH_INSERTION`.
