# S3 v0.2 Evaluation Report

> **S3 = Stage 3, Evidence Verification & Temporal Truth（证据验证与时间真值）**  
> Verifier: `s3-structured-semantic-v0.2.0`  
> Status: **FAIL — fresh generalization is unsafe**

## 术语表

- **Verifier（证据验证器）**：判断证据是否真正支持某个候选医学结论的组件。
- **Regression set（回归集）**：已经参与过设计/调试，只用于确认旧能力不退化的数据。
- **Fresh held-out（新鲜留出集）**：在 verifier 实现后冻结、首次运行前未用于修改 verifier 的数据，用来观察真实泛化。
- **False support（错误支持）**：证据不支持甚至反驳候选结论，但 verifier 却判为 `DIRECT_SUPPORT（直接支持）`。
- **Scope expansion（适用范围扩张）**：把只在有限条件下成立的证据扩大成更强或更广的结论。
- **Temporal supersession（时间版本替代）**：新版本明确替代旧版本后，旧版本不能继续被当成当前真值。
- **Causality escalation（因果升级）**：把相关性、信号或观察性关联错误升级成因果结论。
- **eGFR = estimated Glomerular Filtration Rate（估算肾小球滤过率）**：常用肾功能指标。
- **CYP3A = Cytochrome P450 3A（细胞色素 P450 3A 酶系）**：参与多种药物代谢，常用于药物相互作用机制判断。
- **PK = Pharmacokinetics（药代动力学）**：研究药物在体内吸收、分布、代谢和排泄过程。
- **PGx = Pharmacogenomics（药物基因组学）**：研究遗传差异如何影响药物暴露、疗效或安全性。

---

# 1. Why v0.2 was built

The v0.1 lexical baseline failed because word overlap could hide a medically meaningful action mismatch.

Example:

```text
evidence:
eGFR <45 → reassess benefit/risk

evidence:
eGFR <30 → discontinue

claim:
eGFR <45 → must discontinue
```

A lexical verifier incorrectly marked this as supported.

v0.2 therefore introduced explicit semantic fields/cues for:

```text
action modality
numeric condition
risk vs diagnosis
causality
incidence
trial registration vs efficacy
temporal supersession
mechanism vs clinical management
pharmacokinetic association vs dose management
```

---

# 2. Performance on the old v0.1 regression set

The structured verifier substantially improved the already-seen 24-item regression set:

```text
relation_accuracy                 91.7%
high_risk_false_support_rate       0.0%
high_risk_false_support_count      0
release_gate                       PASS
```

Only two errors remained, both false negatives / over-conservative behavior rather than dangerous false support.

This result looked strong, but it is **not sufficient evidence of generalization** because the v0.1 failure modes were already known when v0.2 was designed.

---

# 3. Fresh held-out result

A separate 24-item v0.2 held-out set was frozen after the verifier implementation and before its first run.

First-run result:

```text
n_items                           24
relation_accuracy                 50.0%
high_risk_negative_items          13
high_risk_false_support_count      2
high_risk_false_support_rate      15.4%
release_gate                      FAIL
```

This is the key S3 result.

> A verifier that scores 91.7% on the known regression set falls to 50% on fresh semantic variants and again produces dangerous false support.

Therefore v0.2 is **not safe for automatic gold construction**.

---

# 4. Two critical false-support failures

## 4.1 Temporal supersession failure

Evidence:

```text
Guideline B supersedes Guideline A for current recommendations.
```

Candidate claim:

```text
Guideline A should still be treated as current after Guideline B supersedes it.
```

Gold:

```text
CONTRADICTS
```

Prediction:

```text
DIRECT_SUPPORT
```

Failure:

```text
SUPERSEDED_AS_CURRENT
```

Root cause:

The verifier detected the word/semantic cue `supersedes` in both evidence and claim and treated it as a matching temporal relation without representing **which document supersedes which** and **which document is asserted as current**.

The missing structure is directional:

```text
subject = Guideline B
predicate = SUPERSEDES
object = Guideline A

therefore:
current = Guideline B
not current = Guideline A
```

A bag of semantic labels is still insufficient.

## 4.2 Observational association → causality failure

Evidence:

```text
An observational analysis reports an association between A and B;
it does not establish that A caused B.
```

Candidate claim:

```text
The observational association proves that A caused B.
```

Gold:

```text
CONTRADICTS
```

Prediction:

```text
DIRECT_SUPPORT
```

Failure:

```text
CAUSALITY_ESCALATION
```

Root cause:

The verifier's causality guard recognized a narrow set of phrases such as `cannot establish causality`, but did not represent generic causal polarity:

```text
association(A,B)
causal_status = NOT_ESTABLISHED
```

The fallback lexical entailment then overrode the intended boundary.

---

# 5. Other fresh-heldout failures

The remaining errors are also informative:

### Numeric / action semantics

- contraindication threshold phrasing was sometimes downgraded to `DOES_NOT_SUPPORT` instead of `CONTRADICTS`;
- existing-user eGFR reassessment rules were not reliably applied to concrete values such as eGFR 40;
- discontinue-vs-reassess action conflicts were sometimes called only `PARTIAL_SUPPORT`.

### Risk / uncertainty semantics

- a bounded statement such as “risk exists but does not diagnose a patient” was not reliably recognized as direct support;
- risk-to-diagnosis overclaim was detected inconsistently when disease names changed.

### Temporal semantics

- `new evidence exists, guideline not yet updated` was not generalized reliably across paraphrases.

### Mechanism / management semantics

- CYP3A inhibitor + substrate → potential PK interaction was sometimes undercalled;
- pharmacogenetic exposure association + management unresolved was undercalled.

### Report interpretation

- `indeterminate lesion` → `malignant` remained a difficult claim-escalation pattern;
- correct preservation of report uncertainty was often marked only partial support.

---

# 6. What this teaches us about S3 architecture

The transition:

```text
lexical overlap
→ semantic cue labels
```

is not enough.

The next verifier must use **directional claim frames** rather than unordered cues.

Recommended representation:

```text
ClaimFrame
├── subject
├── predicate / action
├── object
├── condition
│   ├── variable
│   ├── operator
│   └── value / range
├── population / use_state
├── modality
│   ├── required
│   ├── recommended
│   ├── not_recommended
│   ├── contraindicated
│   ├── risk_increase
│   └── possible
├── causal_status
│   ├── causal
│   ├── association
│   ├── signal_only
│   └── not_established
├── temporal_status
│   ├── current
│   ├── superseded
│   └── historical
└── evidence_scope
```

Then evidence verification becomes fieldwise comparison:

```text
evidence frame
vs
candidate frame
        ↓
exact / entailed / incompatible / missing
        ↓
DIRECT_SUPPORT / PARTIAL_SUPPORT / CONTRADICTS / DOES_NOT_SUPPORT
```

---

# 7. Release decision

S3 v0.2 must **not** automatically approve claims for Knowledge Graph insertion or training-data gold.

Current hard rule remains:

```text
High-risk False-Support Rate must equal 0
```

Fresh held-out result:

```text
15.4% → FAIL
```

Therefore:

> **S3 is now evaluated, but not release-ready.**

This failure is a successful outcome for the platform evaluation architecture: it prevents a verifier that looked strong on regression data from silently contaminating downstream truth.

---

# 8. Next experiment: S3 v0.3

Do not tune v0.2 on the current held-out set and continue calling it held-out.

The current 24-item v0.2 set is now frozen as a **diagnostic/regression set**.

S3 v0.3 should:

1. implement directional `ClaimFrame` extraction;
2. separate evidence-frame parsing from candidate-frame parsing;
3. compare action, threshold, causal polarity, subject/object and temporal direction explicitly;
4. create a **new untouched shadow held-out set** after implementation;
5. require:

```text
High-risk False-Support Rate = 0
Relation Accuracy >= 80%
```

before S3 can become `READY_FOR_KG_TRUTH_INSERTION`.
