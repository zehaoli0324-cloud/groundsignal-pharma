# S5 v0.7.3 — Lineage Detector Development Calibration

Status: **DEVELOPMENT CALIBRATION PASS / NOT FRESH / RELEASE BLOCKED**

## 术语表

- **Lineage（数据血缘）**：一个训练案例是否由受保护 benchmark 内容改写、裁剪或组合而来。
- **Hard negative（困难负例）**：与 held-out 同主题、同模板，但属于允许训练的 dev 分区；用于测误拦截。
- **Protected-exclusive evidence（受保护集专属证据）**：出现在 held-out/regression、但不在允许 dev 语料中的字段、片段或锚点。
- **TF-IDF — Term Frequency–Inverse Document Frequency（词频–逆文档频率）**：把文本转成稀疏向量的可复现基线；本轮不是神经语义模型。
- **Cross-validation（交叉验证）**：按 family 分组轮换训练/验证，减少同一案例家族同时落入训练与验证造成的虚高。
- **p95 latency（第 95 百分位延迟）**：95% 样本的运行时间不超过该值。

## 1. Why v0.7.3 was required

The v0.7.2 repair passed its deliberately small exposed probe: five contaminated variants and two
clean negatives. Before authoring another fresh suite, that detector was expanded to 36 same-family
allowed-dev hard negatives. Its first broader development observation was:

```text
clean dev hard negatives       36
BLOCK                           23
REVIEW                          11
ALLOW                            2
false-block rate            63.89%
review rate                 30.56%
```

This is retained in `calibration-first-observation-v0.7.3.json`. It is not fresh evidence and does
not receive a new S5-F failure identifier. The failure mattered because a detector that blocks shared
family templates would make the explicitly allowed dev split unusable.

## 2. Generic repair

`scripts/s5_lineage_detector_v073.py` builds one protected-reference index and an explicit allowed-dev
corpus. A hard block now requires one of:

1. an exact protected semantic core;
2. an exact field present only in protected data;
3. an exact or anchored near-match span present only in protected data;
4. a high record/field match supported by protected-exclusive anchors.

Fields or sentences already present in dev are not treated as proof of held-out derivation. Empty or
null fields no longer count as exact matches. Span comparison uses precomputed normalized content and
fast token/character overlap instead of all-pairs `SequenceMatcher`.

The same rule runs independently at policy construction and authenticated export validation.
v0.7.2 builder/exporter entry points were preserved as versioned files so its committed metrics remain
reproducible after current entry points advance.

## 3. Calibration design

```text
public/exposed families                         15
protected heldout/regression references         30
allowed dev references                          45
attributable contaminated variants             163
clean/shared-template hard negatives            62
future fresh-suite content used                  0
```

Six transformation families were generated deterministically: presentation-only change, prompt
paraphrase, single evidence-field reuse, evidence/graph composition, prompt-span reuse and distributed
fragment reuse. When copied content was already present in dev, it was labeled allowed/shared rather
than falsely declared held-out-exclusive.

## 4. Method comparison

| Method | Contamination recall | Clean false-block | Clean review | Interpretation |
|---|---:|---:|---:|---|
| Exact semantic core | 18.40% | 0.00% | 0.00% | misses paraphrase and partial reuse |
| Lexical record, grouped CV | 18.40% | 0.00% | 27.42% | whole-record threshold is too blunt |
| TF-IDF vector baseline, grouped CV | 25.77% | 4.84% | 20.97% | modest gain; insufficient for hard gate |
| Learned pair logistic model, grouped CV | 96.93% | 0.00% | 0.00% | strong development comparator; not used as opaque production gate |
| Protected-exclusive explainable hybrid | 100.00% | 0.00% | 0.00% | selected development candidate |

`CV` means family-grouped cross-validation. The selected hybrid's 100% applies only to this deterministic
development/exposed transformation set. It is not unseen generalization evidence.

No neural embedding or cross-encoder was integrated: the repository has no frozen, licensed,
reproducible model artifact for CI. The absence is recorded instead of silently downloading a mutable
model. The learned logistic comparator is retained in the raw metrics, but the production hard gate
uses directly inspectable field/span/anchor reasons.

## 7. Interpretation and next boundary

v0.7.3 closes the development-readiness gap required before the next freeze: broader clean negatives,
transformation breakdown, grouped algorithm comparisons, index size and latency are now reproducible.
It does not convert any prior fresh FAIL into PASS.

After this implementation is committed and CI-confirmed, the next valid evidence is a new post-freeze
S5 lineage suite whose transformations are not present here. Its first observation must be immutable.
Even a fresh structural PASS would not fabricate `gold_approved`; gold review remains independent.
