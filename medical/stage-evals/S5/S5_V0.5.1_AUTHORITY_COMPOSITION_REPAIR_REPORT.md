# S5 v0.5.1 Authority-Composition Repair Report

Evidence class: **development exposed regression**. This is not fresh evidence.

## Historical boundary

The immutable S5 v0.5 first observation remains `medical/stage-evals/S5/fresh-first-observation-v0.5.json` with Git blob `c300d301cb6bf23e5ec1cc0472666f44a1148e77`. It recorded independent fresh failures S5-F16 through S5-F19. v0.5 is permanently exposed and is used here only as regression evidence.

## Generic repair

S5-F16 and S5-F17 were repaired by changing ordinary-source authorization from a loader-context capability into an exact source binding. The export boundary now reloads the externally allowlisted ordinary source and requires the in-memory case, `case_id`, canonical payload digest, source path and Git blob identity to match. Copying `_training_export_context` to another case no longer transfers authority.

S5-F18 was repaired at two independent boundaries. `s5_trust_policy.py` now parses ordinary source `case_id` values while building a policy and rejects benchmark/ordinary or ordinary/ordinary collisions. `export_training_data.py` performs the same namespace validation when authenticating policy content. The serialized policy shape for valid historical policies is intentionally unchanged, preserving v0.4.1 rebuild compatibility.

S5-F19 was repaired by canonical path containment in both the policy builder and materializer. A manifest case path must resolve inside the exact declared family directory, not merely somewhere under the broad family root. This also closes sibling-family traversal and symlink/canonicalization escape classes.

## Interpretation

This version repairs the known authority-composition failures without converting exposed evidence into fresh evidence. The valid-source output contract remains stable; the changes are fail-closed identity and containment checks rather than per-case exceptions.

A PASS here does **not** establish S5 bounded release. The next structural proof must be a genuinely new suite authored only after the v0.5.1 implementation is frozen. Gold review remains an independent release blocker and no approval is fabricated.

## Next fresh attack classes

The next post-freeze suite should target compositions not present in v0.5: ordinary-source aliasing through multiple paths, policy/registry time-of-check-to-time-of-use replacement, Unicode or canonical-path identity ambiguity, case identity reuse through transformed/derived source representations, and source replacement between policy validation and export. Baseline split guards, decision-contract alignment, prompt-gold containment and gold-review containment should remain controls.
