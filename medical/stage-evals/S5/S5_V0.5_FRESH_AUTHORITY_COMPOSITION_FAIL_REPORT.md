### S5-F16 — ordinary payload mutation survives authentication

The canonical ordinary source was loaded through the authenticated registry, then its in-memory prompt was changed. Export remained allowed.

The ordinary-source branch verifies that the backing file path/blob still matches policy, but it never verifies that the case object being exported is still the same payload as that file.

### S5-F17 — ordinary-source context is transferable

A raw heldout benchmark case borrowed `_training_export_context` from the valid ordinary source and became exportable.

This is a stronger form of F16: the context behaves as a bearer capability. Possessing a valid context is sufficient even when the carrying case payload is unrelated to the authenticated ordinary file.

### S5-F18 — case identity is not reserved across ordinary and benchmark namespaces

A new byte-distinct ordinary fixture reused the `case_id` of an authenticated heldout benchmark case. Both `build_policy()` and `_validate_policy_content()` accepted the policy content.

The current byte-collision guard prevents an exact benchmark blob from being reclassified as ordinary, but a semantically different file can still claim the same benchmark identity.

### S5-F19 — declared-family path containment is incomplete

A manifest for declared family A referenced a case under non-member sibling family B using `../`. Policy construction accepted it, and the materializer emitted a case whose provenance points across the declared family boundary.

Containment is currently enforced only against the broad `family_root`, not the specific declared family directory.

## Required generic repair

1. Bind ordinary-source authorization to the exact case payload, not only a path/blob context token.
2. Make `_training_export_context` non-transferable by reconstructing/validating the case from the authenticated source before export.
3. Reserve `case_id` globally across benchmark and ordinary authenticated sources.
4. Require every manifest case path to remain inside its declared family directory in both policy construction and materialization.
5. Rerun v0.5 only as exposed regression; then freeze the repair and create another genuinely new post-freeze boundary suite before any bounded S5 structural release claim.

Gold review remains an independent blocker.
