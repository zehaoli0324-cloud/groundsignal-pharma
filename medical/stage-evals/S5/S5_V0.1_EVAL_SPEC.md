# S5 v0.1 — Benchmark Factory Development Boundary Audit

## Evidence class

`development` only. This is the first S5-specific audit of the already exposed P0 case-family repository. It is **not** a fresh held-out or shadow-held-out evaluation. The existing `split=heldout` P0 cases are already present in the repository and can never be re-labelled as fresh evidence.

Implementation/data snapshot under audit: `9e8aef6ee4e54dd6fe01eb6749368d2c15471762`.

## Purpose

S5 converts user needs and verified truth into diagnostic benchmark cases. Before measuring model performance, the factory must prove that benchmark boundaries are machine-enforced. A structurally valid JSON collection is insufficient if held-out cases can leak into training exports, if release-grade gold is not approved, or if decision-node contracts are optional.

## v0.1 release gates

1. **P0 materialization integrity** — reuse `scripts/validate_medical_case_families.py`; expect 12 families, 60 cases, 5 cases per family, and rubric `medical-clinical-v0.2`.
2. **Family composition** — every family must contain exactly 3 development, 1 regression, and 1 held-out case.
3. **Held-out policy metadata** — every family must declare a non-empty leakage rule and held-out variable(s).
4. **Difficulty metadata** — every family must declare at least four target capabilities and four failure hypotheses. This is a composition check, not proof that a frontier model finds the cases difficult.
5. **Split provenance binding — HARD GATE** — `family_id` and `split` must be schema-bound properties of a materialized case, not only annotations in the family manifest.
6. **Training-export held-out guard — HARD GATE** — a synthetic case explicitly marked `split=heldout` must be rejected by the training-data export path even if its training candidate is marked approved.
7. **Gold readiness — HARD GATE** — a release-grade S5 suite requires explicit `gold_approved` family status. `gold_review_needed` is not silently upgraded.
8. **Decision-node contract — HARD GATE** — the case schema must require `graph_eval`, and the graph contract must require `required_node_ids`, `required_edge_ids`, and `expected_reasoning_path`.
9. **Prompt gold-leakage probe** — a sentinel placed only in `expected_behavior`, `graph_eval`, `safety`, and `scoring` must not appear in the model-facing prompt produced by `model_harness.py`.

## Decision rule

Any failure of gates 5–8 blocks S5 release and blocks downstream components from automatically treating S5 `heldout` or `regression` labels as release-grade partitions. Average percentages cannot override these hard gates.

## Freshness protocol after repair

If v0.1 fails, preserve the raw result, failure taxonomy, and stage status first. Repair only in a later version. The v0.1 cases then become exposed regression material. Only after a repaired implementation is frozen may a newly created, previously unseen family/suite be called fresh held-out; its first observation is immutable.
