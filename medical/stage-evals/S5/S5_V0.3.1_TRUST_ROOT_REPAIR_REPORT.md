## Generic repair

### External trust policy

`medical/configs/s5-trust-root-v0.3.1.json` is now the default export trust root. Benchmark cases do not get to select their own authority. The policy separately records trusted suite, family manifest and source-case Git blob identities. Ordinary non-benchmark training fixtures also require explicit path + blob allowlisting.

`scripts/s5_trust_policy.py` provides a generic builder for future operator/evaluation policies. A future fresh suite can therefore be registered after an implementation freeze without changing the exporter code; the policy is an external input to the trust decision, not case-local metadata.

### S5-F8 — location laundering

`load_cases()` no longer treats an arbitrary non-`case-families` path as trusted. An unpartitioned source is loadable for training only if the external policy explicitly contains that repository-relative path and its Git blob identity. Copying a held-out raw case to an ordinary temporary location is rejected.

### S5-F9 — self-authenticated digest

The embedded `materialized_payload_sha256` is no longer treated as proof of truth. Before benchmark export, the exporter resolves the externally trusted suite, family manifest and source case, then reconstructs the complete expected materialized case. The current payload must exactly equal that source-authoritative reconstruction. Mutating a prompt and recomputing the embedded digest therefore remains blocked.

### S5-F10 — suite identity

`benchmark_provenance.suite_id` must resolve to a suite registered in the external trust policy, and the suite file itself must match the registered Git blob. A forged suite id cannot authenticate itself by recomputing local hashes.

### S5-F11 — foreign manifest substitution

A manifest is accepted only when it is the registered manifest for a family that is a member of the trusted suite, and its Git blob plus source-case blob match the external policy. A repo-local decoy manifest that happens to reuse the same case id cannot become authority.
