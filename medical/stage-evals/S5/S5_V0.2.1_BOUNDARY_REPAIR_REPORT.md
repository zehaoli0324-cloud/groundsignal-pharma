## Generic implementation changes

### S5-F4 — provenance authority

`export_training_data.py` no longer trusts case-local `split` or `training_eligible` as partition authority. For S5 benchmark cases it resolves the recorded source manifest inside the repository, verifies manifest and source-case SHA-256 digests, finds the authoritative case reference, and requires the local provenance split to match the manifest split.

A held-out case relabeled locally to `dev` is rejected even if `training_eligible=true` is also forged.

### S5-F5 — fail-closed split identity

S5 benchmark split handling now uses an explicit allowlist:

- `dev` — potentially training-eligible;
- `regression` — blocked;
- `heldout` — blocked;
- missing or unknown benchmark split — blocked.

A partitioned case with stripped benchmark provenance is rejected. Ordinary non-benchmark training fixtures remain supported only when loaded through the exporter's trusted file-loader path; a direct unprovenanced case cannot self-assert trust.

### S5-F6 — materialized payload integrity

`materialize_s5_cases.py` now computes `materialized_payload_sha256` over the complete canonical materialized case, excluding only the digest field itself. Training export recomputes the digest before emitting a row. Any post-materialization change to prompt, context, expected behavior, provenance, or other payload fields invalidates the digest and is rejected.

Source manifest and source case digests remain independently checked.

### S5-F7 — decision-contract semantic alignment

`clinical-case.schema.json` now requires **either**:

1. a complete `graph_eval` decision contract, or
2. a typed `decision_contract_exemption` with rationale.

This matches `materialize_s5_cases.py`, which already accepted a valid typed exemption. The schema no longer unconditionally requires `graph_eval` when a legitimate exemption exists.
