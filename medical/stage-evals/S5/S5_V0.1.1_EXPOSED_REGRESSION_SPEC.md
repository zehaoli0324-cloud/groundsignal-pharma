# S5 v0.1.1 — Structural Repair Exposed Regression Spec

> Stage: S5 Controlled Case / Benchmark Factory  
> Evidence class: development exposed regression  
> Fresh held-out: **NO**  
> Historical first observation preserved: S5 v0.1 at commit `811a755120210a14863a485e31c42ed5d3dd5f28`

## Purpose

Repair the three structural boundary failures observed in S5 v0.1 without changing any P0 case into fake fresh evidence and without inventing clinical/gold approval.

The repair is considered successful only if the benchmark factory makes split provenance and decision contracts machine-enforced, and if missing gold approval blocks release automatically.

## Reused inputs

- 12 already exposed P0 families / 60 cases.
- P0 source snapshot: `9e8aef6ee4e54dd6fe01eb6749368d2c15471762`.
- Existing `gold_review_needed` statuses are preserved.

These cases are regression fixtures only. Their `heldout` labels describe partition intent, not freshness.

## Gates

### G1 — Materialization provenance

A case used downstream must be materialized by joining the raw case with its family manifest and suite contract. Materialized output must bind:

- `suite_id`;
- `family_id`;
- `split`;
- variant type;
- source manifest/case paths;
- SHA-256 content hashes;
- materializer version;
- training eligibility.

Expected P0 counts: 12 families, 60 cases, dev 36 / regression 12 / heldout 12. Only dev is training-eligible.

### G2 — Training export partition guard

Even with `training_candidate.review_status=approved`:

- `heldout` must be rejected;
- `regression` must be rejected;
- a materialized `dev` case may be exported and must preserve source family/suite/split provenance.

The guard must be generic by partition semantics, never by hard-coded case ID.

### G3 — Decision-contract schema

`graph_eval` is schema-required. The schema must require:

- `required_node_ids`;
- `required_edge_ids`;
- `expected_reasoning_path`.

The materializer accepts a missing decision contract only through an explicit typed exemption with a rationale; silent omission is invalid.

### G4 — Gold release predicate

Release requires explicit `status=gold_approved` for every family in the suite. Approval must never be inferred from source verification, synthetic-fixture quality, case integrity, or model score.

For the current P0 snapshot, the correct result is `BLOCKED_GOLD_REVIEW` because 0/12 families are gold-approved.

### G5 — Prompt gold leakage regression

A sentinel placed only in gold/evaluation-only fields must remain absent from the model-facing prompt produced by `model_harness.py`.

## Decision

`STRUCTURAL PASS` requires G1–G5 to pass. This does **not** make S5 release-ready. After structural PASS the correct stage state remains:

```text
S5 structural boundary      PASS
S5 gold release gate        BLOCKED_GOLD_REVIEW
fresh S5 release evidence   NOT YET CREATED
S6 automatic trust          BLOCKED
```

Only after this implementation is frozen may a genuinely new S5 family/suite be created for first-use fresh held-out evaluation.
