# S5 v0.2 — Post-freeze Fresh Boundary Evaluation Spec

## Scope

This evaluation is the first use of a new synthetic S5 benchmark-boundary family against the frozen S5 v0.1.1 implementation at commit `37a89d14b37a1e2b3b823e933b4a7bfbd3038af8`.

“Fresh” means the fixtures were created only after the target implementation was frozen and were not part of the exposed P0 suite. It does **not** mean third-party expert review, clinical validation, or real-patient evidence.

The target implementation is not modified in this version. The purpose is to test whether the structural repair generalizes beyond the 12 exposed P0 families.

## Hard gates

The evaluation checks, in order:

1. frozen target identity;
2. fresh family referential integrity;
3. fresh materialization and decision-contract coverage;
4. baseline dev/regression/heldout export behavior;
5. provenance tamper resistance;
6. fail-closed behavior for missing or unknown split authority;
7. materialized-payload integrity before training export;
8. schema/materializer agreement on typed decision-contract exemptions;
9. model-prompt gold leakage;
10. gold-release containment.

A fresh S5 structural PASS requires every hard gate to pass. A baseline guard passing is insufficient if an adversarial mutation can bypass the boundary.

## Adversarial probes

The suite intentionally probes generic interface failures rather than hard-coding one medical answer:

- relabel a materialized heldout case as `dev` and flip `training_eligible=true`;
- remove benchmark provenance and provide only top-level `split=dev`;
- supply an unknown provenance split (`train`) with `training_eligible=true`;
- mutate a materialized dev payload after source-hash materialization;
- construct an exemption-only decision contract accepted by the materializer and compare it with the JSON schema;
- place a sentinel only in gold/scoring fields and test whether it reaches the model-facing prompt.

Controls confirm that an unchanged heldout split remains blocked even if eligibility is flipped, and that `training_eligible=false` remains blocking after a split flip.

## First-observation policy

`fresh-first-observation-v0.2.json` is immutable evidence. Once this suite is run, it becomes exposed regression data.

If the result is FAIL:

- commit the raw metrics and failure taxonomy;
- keep S5 release and S6 automatic trust blocked;
- do not repair the implementation in the same version;
- repair generically in a later version;
- reuse this suite only as exposed regression;
- create a second new post-freeze suite after the repair is frozen.

No PASS can be inferred from synthetic source quality, model score, or freshness. Gold release still requires explicit review status.
