## New hard-gate failures

### S5-F8 — LOCATION_LAUNDERING_TRUST_BYPASS

A raw heldout benchmark case was copied to an ordinary filesystem path and then loaded through the exporter's trusted unpartitioned loader path. The copied heldout case became exportable.

Root cause: benchmark/non-benchmark trust is inferred from loader location/context rather than an external source authority.

### S5-F9 — SELF_AUTHENTICATED_PAYLOAD_DIGEST_RECOMPUTABLE

A materialized dev payload was modified after materialization. The attacker recomputed `materialized_payload_sha256` using the public canonical hash function. The modified payload remained exportable.

Root cause: the integrity digest is stored inside the object it authenticates. It detects accidental mutation but does not authenticate against an independent trust root.

### S5-F10 — SUITE_IDENTITY_NOT_AUTHENTICATED

`benchmark_provenance.suite_id` was replaced by an attacker-controlled value and the embedded payload digest was recomputed. Export remained allowed.

Root cause: exporter verifies family manifest/source identity but does not verify the declared suite against an authoritative suite contract.

### S5-F11 — FOREIGN_MANIFEST_AUTHORITY_SUBSTITUTION

The legitimate heldout materialized case was redirected to a new repo-local foreign manifest that was not listed in `S5-FRESH-BOUNDARY-v0.3`. That manifest declared the same `case_id` as `dev`. After updating source hashes and the embedded digest, the heldout payload became exportable.

Root cause: repository locality is treated as sufficient authority. Family manifest membership is not cryptographically or structurally bound to the intended suite.

## Interpretation

v0.2.1 successfully repaired the exposed F4-F7 probes, but v0.3 shows that the current boundary still relies on self-asserted or repo-local authority. The next repair must introduce an external authoritative chain rather than another case-local field.

A generic repair should at minimum:

1. remove location-derived implicit trust for unpartitioned training sources and replace it with an explicit external allowlist/policy;
2. bind materialized payload content back to authoritative source content, not only to a recomputable embedded digest;
3. bind every materialized benchmark case to an authoritative suite contract (`suite_id`, suite path/hash, family membership, split policy);
4. reject manifests that are not members of that authenticated suite;
5. preserve ordinary non-benchmark training fixtures only through explicit policy, not automatic path classification.

The v0.3 suite is now exposed and must never be reused as fresh evidence after repair.
