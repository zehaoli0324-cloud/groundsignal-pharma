## Generic repairs

1. **Canonical identifier boundary** — `case_id` must already be Unicode NFC (Normalization Form C) canonical at policy construction and protected export validation. Namespace uniqueness is evaluated on that canonical representation.
2. **Data-lineage boundary** — benchmark cases receive a stable semantic-core fingerprint over task type, data origin, patient context, evidence snapshot, interaction, expected behavior, graph evaluation, safety and scoring. An ordinary source with the same core is rejected even if outer bytes, `case_id`, title, tags or lineage annotations differ.
3. **Atomic authority snapshot** — security-sensitive registry, policy, suite, manifest, source-case and ordinary-source JSON are read once into bytes; the Git-blob hash and JSON parse are both computed from that same snapshot. This removes the tested check/read TOCTOU window.
4. Existing exact blob, exact payload, authenticated registry and declared-family containment controls remain in force.
