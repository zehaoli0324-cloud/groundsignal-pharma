# S2 v0.3 Evaluation Report

> **S2 = Stage 2, Knowledge Search & Source Routing（知识搜索与来源路由）**  
> Date: 2026-09-05  
> Status: **CONDITIONAL PASS — substantially improved, but not a claim of comprehensive medical retrieval**

## 术语表

- **Intent Router（意图路由器）**：先判断用户的信息需求属于哪一类，再按来源策略选择权威数据源。
- **Source Policy（来源策略）**：把受控的医学信息意图映射到一个或多个优先权威来源。
- **API = Application Programming Interface（应用程序编程接口）**：程序访问外部数据库或服务的标准接口。
- **SPL = Structured Product Labeling（结构化药品标签）**：美国药品标签使用的结构化文档格式。
- **XML = Extensible Markup Language（可扩展标记语言）**：SPL 文档的机器可解析文本表示形式之一。
- **LOINC = Logical Observation Identifiers Names and Codes（检验与临床观察标准编码体系）**。
- **RxNorm（美国国家医学图书馆临床药物标准术语系统）**：用于药物品牌名、通用名、成分和剂型等概念标准化。
- **DDI = Drug–Drug Interaction（药物-药物相互作用）**。
- **FAERS = FDA Adverse Event Reporting System（美国食品药品监督管理局不良事件报告系统）**。
- **QTc = corrected QT interval（校正后的 QT 间期）**。
- **Recall@K（前 K 个结果召回率）**：目标来源或证据是否出现在前 K 个检索结果中。
- **held-out（留出集）**：在开发/调规则时不使用的数据，用来观察泛化。
- **regression（回归测试）**：系统修改后反复运行冻结测试，确认旧能力没有被破坏。

# 1. v0.3 architecture change

v0.2 exposed that direct keyword → source routing was brittle. v0.3 separates semantic intent from source policy:

```text
User query
   ↓
Bilingual semantic feature extraction
   ↓
Intent classification
   ↓
Source Policy
   ↓
Ranked authoritative source families
   ↓
Live retrieval
   ↓
Current document/version selection
   ↓
Critical passage retrieval
```

Implemented assets:

- `medical/stage-evals/S2/intent-features-v0.3.json`
- `medical/stage-evals/S2/source-policy-v0.3.json`
- `scripts/s2_intent_router.py`
- `scripts/eval_s2_intent_routing.py`
- `medical/stage-evals/S2/intent-routing-heldout-v0.3.json`
- `medical/stage-evals/S2/dailymed-truth-retrieval-v0.3.json`
- `scripts/s2_dailymed_truth_retrieval.py`
- `scripts/eval_s2_dailymed_truth_retrieval.py`

The router remains deterministic and interpretable. It is an engineering baseline, not a claim that open-ended medical language has been solved.

# 2. Fresh intent-routing held-out

A new 24-query set was frozen **after the v0.3 intent router was implemented and before its first run**.

First-run result using `intent-first-s2-v0.3.0`:

```text
n_queries                         24
intent_accuracy                   0.917
primary_source_recall_at_1        0.917
acceptable_source_recall_at_3     0.917
critical_source_miss_rate         0.000
high_risk_queries                 4
release_gate                      PASS
```

This is materially better than the v0.2b shadow-heldout result from the previous direct keyword router:

```text
v0.2b Primary Source Recall@1     0.733
v0.3  Primary Source Recall@1     0.917
```

The two v0.3 failures are deliberately preserved rather than post-hoc tuned away.

## Failure 1 — observation normalization phrasing

Query:

```text
我要把尿白蛋白/肌酐比作为结构化 observation 存进数据库，需要标准编码，
不是问结果高低怎么解释。
```

Gold:

```text
OBSERVATION_TERMINOLOGY_NORMALIZATION → LOINC
```

Observed:

```text
GENERIC_MEDICAL_LITERATURE → PubMed
```

Root cause:

> The feature layer recognized `标准编码/结构化` as normalization but did not independently infer that the named laboratory observation itself was an observation-identity task.

Failure family:

```text
CONCEPT_TYPE_INFERENCE_GAP
```

## Failure 2 — drug normalization phrasing

Query:

```text
Nexium、esomeprazole 和 esomeprazole magnesium 想统一成规范药物概念和成分，
应该走哪个标准系统？
```

Gold:

```text
DRUG_TERMINOLOGY_NORMALIZATION → RxNorm
```

Observed:

```text
GENERIC_MEDICAL_LITERATURE → PubMed
```

Root cause:

> The feature layer recognized drug identity terms but required a narrower normalization trigger than the natural phrase `统一成规范药物概念`.

Failure family:

```text
NORMALIZATION_PARAPHRASE_GAP
```

These errors do not include any high-risk critical-source miss.

# 4. Current-version and critical-passage retrieval

v0.3 adds a real DailyMed truth-retrieval layer for three high-risk source-backed scenarios:

1. metformin extended release — renal impairment / eGFR threshold;
2. apixaban / Eliquis — NSAID-associated bleeding-risk evidence;
3. sertraline — serotonin-syndrome warning.

For each SET ID, the runner:

```text
DailyMed version history
       ↓
identify latest SPL version
       ↓
retrieve SPL XML
       ↓
check XML version == latest history version
       ↓
parse document sections
       ↓
rank sections for the preregistered clinical information need
       ↓
measure critical passage Recall@1 / Recall@3
```

## 4.1 Adapter bug discovered before semantic evaluation

First run:

```text
3 / 3 = HTTP 406 Not Acceptable
```

The main DailyMed search API was healthy at the same time. Root cause was therefore isolated to the new adapter: it over-constrained HTTP content negotiation with narrow `Accept` headers even though the endpoint representation was already selected by `.json` / `.xml` URL suffix.

Fix:

```text
Accept: */*
```

No passage-ranking rule, gold section, or held-out intent item was changed for this fix.

This is a concrete example of stage-level evaluation separating an infrastructure-adapter bug from a semantic medical retrieval bug.

## 4.2 Second run after protocol fix

```text
n_tests                                              3
source_availability_rate                             1.000
current_version_consistency_rate_given_available     1.000
critical_passage_recall_at_1_given_available         1.000
critical_passage_recall_at_3_given_available         1.000
infrastructure_failures                              0
release_gate                                         PASS
```

All three current SPL XML documents agreed with the latest version returned by the corresponding DailyMed history endpoint.

All three preregistered critical evidence sections were ranked at position 1.

# 5. What is now proven vs not proven

## Proven for the current suites

- the v0.3 intent-first architecture improves fresh routing generalization over the previous direct keyword router;
- no critical source miss occurred in the 4 high-risk fresh routing queries;
- the existing 10-test official-source retrieval suite remains functional;
- DailyMed history + current SPL retrieval can be executed programmatically;
- current-version consistency can be independently evaluated;
- critical-section retrieval can be evaluated separately from source routing;
- the first 3 high-risk DailyMed cases reached Recall@1 = 1.0.

## Not proven

- arbitrary medical user language routing;
- comprehensive drug-label coverage;
- passage retrieval across all source families;
- robust ranking under large distractor corpora;
- multi-document contradiction retrieval;
- automatic jurisdiction disambiguation in ambiguous questions;
- LOINC/RxNorm entity normalization itself (only source routing is evaluated here);
- clinical expert approval of every downstream gold claim.

# 7. Current decision

S2 is now best described as:

> **CONDITIONAL PASS / EVALUATED PROTOTYPE**

It is strong enough to begin S3 evaluation on a controlled source set, but it should continue to regress in parallel.

Why not mark it fully complete?

- fresh intent routing is 91.7%, not 100%;
- current-version / passage retrieval has only 3 DailyMed high-risk examples;
- source-family diversity at passage level is still narrow.

The correct engineering strategy is therefore:

```text
freeze S2 v0.3 evidence
        ↓
start S3 Evidence Verification Eval
        ↓
keep expanding S2 passage/version regression in parallel
```

Do not delay all downstream work until S2 becomes a comprehensive medical search engine.

# 8. Next stage handoff

S3 should receive a **frozen verified document/passage bundle**, not raw internet search output.

First S3 eval should test:

```text
Document + critical passage
        ↓
atomic claim extraction
        ↓
claim entailment
        ↓
claim scope
        ↓
numeric threshold / negation / exception
        ↓
temporal status
        ↓
contradiction / supersession
```

Recommended first S3 vertical slice:

- metformin renal threshold;
- apixaban + NSAID bleeding-risk claim;
- sertraline serotonin-syndrome warning;
- FAERS signal ≠ causality negative control;
- trial-registration ≠ efficacy negative control.

This will directly evaluate whether **finding the right evidence** is followed by **interpreting that evidence correctly**.
