## 术语表

- **Temporal frontier（时间前沿）**：同一 truth slot 中当前最新、仍具有决策意义的状态集合。
- **CONTESTED（争议态）**：同一 slot、同一有效日期存在互相冲突且尚未解决的命题，不能选一个作为自动真值。
- **Contested-set closure（争议集合闭包）**：已有争议集合出现第三个同日期冲突时，新命题必须加入同一争议集合，而不能单独变成 ACTIVE。
- **ACTIVE（当前有效）**：当前可作为该 slot 的单一活动真值的边。
- **SUPERSEDED（已取代）**：被更晚时间前沿取代、只保留历史与 provenance（来源链）的边。

## 1. Why v0.1.1 exists

S4 v0.1 development passed 12/12, but its first independent fresh held-out failed 18/20. The two immutable failures were:

```text
S4F-004  late older fact became ACTIVE behind a newer unresolved contradiction
S4F-005  third same-date conflicting fact became ACTIVE instead of joining CONTESTED
```

Both failures share one state-machine defect: v0.1 treated `ACTIVE` and unresolved `CONTESTED` edges as separate update paths instead of one current per-slot temporal frontier.

No historical v0.1 fresh artifact, gold label, or first-run result was changed.

## 2. Structural repair

v0.1.1 introduces a single frontier operator over:

```text
CURRENT_FRONTIER_STATES = {ACTIVE, CONTESTED}
```

For every slot:

```text
new.effective_at < frontier_date
→ INSERTED_HISTORICAL / SUPERSEDED
→ never reactivate behind unresolved newer truth

new.effective_at == frontier_date and distinct claim
→ CONTESTED
→ all same-date current frontier peers link to the new conflict
→ no ACTIVE survives in that contested frontier

new.effective_at > frontier_date
→ supersede the previous current frontier, whether ACTIVE or CONTESTED
→ new edge becomes ACTIVE
```

Idempotent same-claim merges still preserve provenance without reactivation. Validation, source review gates, partition isolation, exact rollback, slot scoping, and provenance requirements are unchanged from v0.1.

The implementation contains no case IDs or exact benchmark sentences.
