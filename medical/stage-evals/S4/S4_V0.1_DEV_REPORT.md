## Decision

**DEVELOPMENT GATE PASS. S4 remains NOT independently released.**

This version adds a guarded truth-ledger update layer for the evaluation-oriented medical knowledge graph. It is intentionally narrower than production graph ingestion. The development suite was created with the implementation in this version, so these results are exposed development evidence and must never be relabeled as fresh held-out evidence.

Automatic unrestricted `free text → S3 → S4 clinical truth` ingestion remains blocked.

## Stage-specific eval contract

S4 v0.1 is evaluated on update semantics that were missing from the snapshot-only canonical builder:

1. current truth insertion;
2. idempotent duplicate ingestion without duplicate edges;
3. newer-version supersession;
4. out-of-order stale update handling;
5. contradiction preservation rather than silent overwrite;
6. mandatory source/passage/version provenance;
7. rejection of non-`DIRECT_SUPPORT` S3 relations;
8. synthetic-vs-external graph partition isolation;
9. exact rollback of the last transaction;
10. jurisdiction-scoped truth;
11. population-scoped truth;
12. rejection of unverified source material.

Release gates for this development version are deliberately strict:

```text
case accuracy                         = 100%
safety gate accuracy                  = 100%
high-risk false accepts               = 0
rollback exactness                    = 100%
contradiction preservation            = 100%
stale active edges                    = 0
suite must remain development-only    = true
```

The ledger uses a semantic slot composed of:

```text
subject
+ predicate
+ population
+ conditions
+ jurisdiction
```

The claim value additionally includes object and polarity. This prevents a U.S. update from incorrectly superseding an E.U. statement, and prevents an adult rule from overwriting a pediatric rule.

For the same semantic slot:

```text
newer effective date        → prior ACTIVE edges become SUPERSEDED
older out-of-order date     → inserted as historical SUPERSEDED truth
same date + different claim → both claims become CONTESTED
same claim + same date      → provenance merges idempotently
```

Contradiction is therefore represented explicitly. The implementation does not resolve disagreement merely because one event arrived later in the pipeline.

## Safety boundary

An event is rejected from the clinical-external partition when any of the following holds:

- source / passage / locator / source-version provenance is missing;
- S3 relation is not `DIRECT_SUPPORT`;
- review state is below `SOURCE_VERIFIED`;
- controlled synthetic truth is routed into the external clinical partition.

This is a fail-closed boundary. It does not establish that `DIRECT_SUPPORT + SOURCE_VERIFIED` is sufficient for unrestricted clinical deployment.

## What this does NOT prove

This version does not prove:

- independent fresh-held-out generalization;
- unrestricted automatic ingestion from arbitrary S3 outputs;
- terminology/entity normalization;
- persistent database concurrency semantics;
- multi-document temporal coreference;
- probabilistic conflict resolution;
- clinical correctness of any real medical claim;
- clinician/expert review.

The existing canonical JSON builder remains a snapshot builder. S4 v0.1 adds controlled update semantics beside it; integration with persistent graph storage is a later step.
