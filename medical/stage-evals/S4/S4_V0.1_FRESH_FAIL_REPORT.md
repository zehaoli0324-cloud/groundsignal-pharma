## 术语表

- **KG — Knowledge Graph（知识图谱）**：以实体、关系和带溯源的事实边组织医学知识。
- **Truth ledger（真值账本）**：负责事实版本、冲突、替换、溯源和回滚的更新层。
- **Fresh held-out（新鲜留出集）**：实现冻结后才创建、此前从未用于开发的独立测试集；首次结果永久保留。
- **CONTESTED（争议态）**：同一语义槽位、同一有效时间存在互相冲突且尚未解决的事实集合。
- **Temporal frontier（时间前沿）**：某语义槽位当前最新、仍有资格约束后续更新的 ACTIVE 或 unresolved CONTESTED 状态。

## 4. Frozen failure taxonomy

### S4-F1 — unresolved CONTESTED frontier is ignored by late historical insertion

Fresh case `S4F-004` first creates two conflicting facts at `2026-03-01`, leaving the slot unresolved and `CONTESTED`. A fact effective `2025-03-01` then arrives late.

Expected semantics: the older fact is historical/superseded and must not become active behind a newer unresolved contradiction.

Observed semantics:

```text
expected final ACTIVE count      0
observed final ACTIVE count      1
observed active object           rule:old
observed stale active edges      1
observed action                  SUPERSEDED_PRIOR
```

General defect: temporal dominance currently inspects newer `ACTIVE` peers but does not treat a newer unresolved `CONTESTED` set as part of the current temporal frontier. Therefore an older arrival can be promoted to `ACTIVE` while newer contradictory evidence is still unresolved.

### S4-F2 — an existing CONTESTED set is not closed under additional same-date conflicts

Fresh case `S4F-005` creates a same-date A-vs-B contradiction and then inserts a third different claim C at the same effective date.

Expected semantics: all three claims belong to one unresolved contested set; no claim is active.

Observed semantics:

```text
expected CONTESTED count         3
observed CONTESTED count         2
expected ACTIVE count            0
observed ACTIVE count            1
observed active object           rule:c
observed third action            SUPERSEDED_PRIOR
```

General defect: same-date contradiction detection currently checks equal-date `ACTIVE` peers but not equal-date `CONTESTED` peers. Once the first pair becomes contested, a subsequent peer can bypass contradiction membership and become active.

### Shared root cause

Both failures arise because `ACTIVE` and unresolved `CONTESTED` are handled as separate local branches rather than as one **current-slot frontier** with explicit temporal and conflict-set semantics.

This is a structural state-transition defect, not a missing keyword or single-case pattern.

## 5. Safety interpretation

All seven must-reject cases remained fail-closed, including corrupted provenance, invalid time, non-supporting S3 relations, and partition leakage. Scope isolation, rollback, provenance merging and partition behavior also remained 100% on this fresh suite.

However, the stale-active failure is sufficient to block release. A knowledge graph must not expose an older claim as active merely because newer evidence is unresolved rather than resolved.

## 7. Next coherent version

Target: **S4 v0.1.1 — Unified Temporal Frontier + Contested-set Closure**.

The repair should generalize state transitions around a single per-slot current frontier:

1. compute the latest effective-date frontier across both `ACTIVE` and unresolved `CONTESTED` edges;
2. force any older arrival behind that frontier to historical/superseded status;
3. add every same-date conflicting claim to the existing contested set rather than creating an active peer;
4. preserve exact rollback, provenance, scope isolation and fail-closed gates;
5. rerun the 12-case development suite plus this 20-case now-exposed fresh suite as regression;
6. only after those development/regression gates pass and v0.1.1 is frozen, create a brand-new fresh held-out suite.
