# GroundSignal 患者多轮复杂评测系统实施任务书 v1.1

日期：2026-09-09。状态：历史增补版，现已与 v1.0 合并为 [统一任务书 v1.2](patient-evaluation-master-taskbook-v1.2.md)。本页保留当时的 v0.1 原型范围，当前实施以 v1.2 为准。

本任务建设一个能够揭示患者会话缺陷的评测系统：既用真实用户问题比较小荷应用与通用模型的表现，也用可记录内部过程的自建系统检验算法改进和工程可靠性。先完成可审查的开发闭环，再按既有流程开展独立测试与人类使用研究。

基础需求、八模块定义、完整指标分母、场景规模、F01–F10 故障库及 W01–W08 工作包继续以 [任务书 v1.0 全文](patient-multiturn-evaluation-taskbook-v1.0.md)为准；[Word 原件](patient-multiturn-evaluation-taskbook-v1.0.docx)保留不变。本版补充最新研究目标、系统归属、当前代码边界及下一批验收任务。实现范围以本版和 [适配方案](../../medical/patient-eval/ADAPTATION_PLAN.md)为准，不能把 v1.0 的完整目标读成当前已完成能力。

## 1. 项目归属和系统结构

并入 GroundSignal，新增 `medical/patient-eval/` 数据与规则区、`scripts/patient_eval/` 执行代码区。共享现有的案例、证据、来源、干预假设和回归标识；通过适配器逐步连接，不重写或削弱既有准入流程。

产品采用一个患者评测入口，内部按八个模块查看结果：语义澄清、主动问询、事实更新、风险边界、证据适用、工具恢复、患者解释、压力稳定。完整会话是综合评测对象，模块专项与诊断回放用于进一步解释失败。一个入口不等于把所有能力压成一个总分。

当前不需要另开一套大项目。将来若部署、团队或受控数据权限需要独立，再拆分服务或仓库；先用模块和合同保证边界。

## 2. 两种观测等级与结论规则

| 接入方式 | 主要对象与材料 | 允许的结论 | 证据边界 |
| --- | --- | --- | --- |
| `instrumented`，内部过程可观测 | 自建系统；实际模型输入、可见状态、检索和工具轨迹、版本、故障与修复回放 | 有匹配对照时，可验证特定条件下的组件故障或算法策略不足 | 注入故障不等于回答必然失败；修复一个组件不等于所有问题同源 |
| `black_box`，黑盒观测 | 小荷应用和其他只能看到界面的平台；完整输入输出、可见引用、服务错误和采集条件 | 确认行为缺陷；用受控比较支持候选原因 | 不能仅从回答实证其内部模型、检索、路由、上下文处理或服务器故障 |

报告的证据等级分为“在本实验条件下已验证”“有对照支持的假设”“待排查”。黑盒的内部算法和工程解释必须保留为假设；可以验证外部输入条件对输出的影响，不能将这种关系直接当作内部实现事实。

例如，用户纠正时间后系统继续使用旧时间，可以确认纠正吸收失败。固定前缀中重述新时间后改善，支持其对历史信息使用存在不足的解释，仍不能证明后台截断。只有自建系统日志显示纠正没有进入实际输入、修复状态更新后相同前缀恢复，才可能确认该条件下的工程问题。

## 3. 小荷与通用模型比较的正式任务

### 3.1 采集方式

首批使用文本问题，人工操作小荷应用与选定通用模型，将完整会话导入共同记录格式。应用程序接口（Application Programming Interface，API）作为另一接入渠道单独登记。应用对应用比较的是端到端产品能力；应用对 API 组合比较不能简写成底层模型排名。

真实用户问题需记录来源及使用依据，完成去标识和人工复核。真实问题改写、完整真实日志和完全合成问题分别计数。公开仓库只保存合成材料、模板、代码和经复核的不可识别汇总；患者原文、图片、录屏、账号信息及关联映射不提交公开仓库。

每次运行登记实际可见的平台与模型名称、应用版本、日期时区、账号模式、记忆/联网/文件等开关、设备网络、重置情况、实验批次及重复编号。不能确认的条件填未知。保存所有轮次、重试、错误与停止原因；不能只挑成功会话。

### 3.2 两条实验轨分开报告

- **自由对话轨**：初始问题与患者事实一致，平台自主追问；采集者依冻结披露规则回答。它检验问询和整体任务能力，允许不同平台走不同合法分支。
- **固定前缀轨**：平台获得相同的合法已披露历史，在指定位置接受歧义、纠正、催促或错误复述探针。它检验局部响应，有助于缩小差异来源，不能替代主动问询评测。

固定前缀通过结构化消息发送，和在应用中粘贴一段引用历史，是不同输入形式，必须分别记录。平台无法控制的系统提示、路由和后台工具属于比较限制，不伪装成已经保持一致。

### 3.3 比较和审核要求

清晰与压力版本按家族配对；预先规定改变的因素。平台和变体顺序随机或平衡，在尽量相近的时间窗口采集，并按预先规定的次数重复。同版本同条件结果才作为同一批次，更新后重新记录。

评分隐藏平台名称和先后位置；临床规则经合适的临床人员审核，分歧保留并裁决。目标平台超时或未完成计目标失败；独立采集器、模拟器或评分器错误才可标记测量无效。未完成人工临床评分时保留未评，不自动通过。

统计按家族配对并保留缺失配对；同一问题的改写、轮次和重复不是新的独立患者样本。真实用户的理解和获益不能由模拟患者说“懂了”或离线高分直接证明。

## 4. 当前代码原型可以做什么

当前核心代码是开发原型：四个合成场景家族，各含清晰版和压力版，共八个变体。它不等于 v1.0 的 24 个开发场景或 72 个研究家族，不代表八模块均已完成临床验收。

| 已有核心 | 当前实际行为 | 结果的用途与限制 |
| --- | --- | --- |
| 数据合同校验 | 使用 JavaScript Object Notation（JSON，结构化数据交换格式）记录场景、会话、评分与比较；检查开发边界和字段 | 结构合法不等于临床真值正确；不能用自填状态绕过正式测试准入 |
| 事实状态机 | 根据已经可见的结构化标注，维护事实来源、未知、冲突和显式纠正 | 测状态算法与工程传递；尚不能证明自动理解患者口语 |
| 检索原型 | Best Matching 25（BM25，基于词项相关性和长度归一化的排序方法），配合中文词项处理、时间和人群适用性过滤 | 合成证据用于检验排序和过滤机制；不是医学证据覆盖或临床检索效果证明 |
| 固定前缀夹具 | 前缀包含事先写好的用户和助手历史；根据可见标注累积状态，只生成最后一条回答 | 可用于回放和机制对照；没有动态生成每轮问答，也不是患者模拟器 |
| 故障和修复对照 | 丢弃纠正事件，并从相同合法前缀进行修复回放；核对实际状态、输入和结果 | 展示工程故障定位；故意损坏的夹具基线不是通用模型能力基线 |
| 黑盒导入与评分 | 人工会话导入统一格式；临床项没有人工标注时保持 `unassessed`，即未评 | 尚未自动采集小荷，也没有真实平台比较结果 |
| 兼容 API 接入 | 明确配置后，将固定合法前缀发给真实模型，生成最后回答 | 本次未调用付费模型；不是自由对话自动化 |
| 诊断和报告 | 保留观测等级、分母、未评、无效和缺失配对；输出家族配对结果与自助重采样区间 | 小规模合成结果用于验证测量程序，不能支持人群泛化或商业模型排名 |

运行入口如下。具体输入合同与完整说明见 [患者评测目录](../../medical/patient-eval/)。

```bash
python -m scripts.patient_eval demo --out /tmp/patient-eval-demo

python -m scripts.patient_eval import --input /path/to/transcripts.json --out /path/to/imported.json

python -m scripts.patient_eval evaluate --suite medical/patient-eval/development/scenarios.json --sessions /path/to/imported.json --out /path/to/report

python -m scripts.patient_eval run-api --suite medical/patient-eval/development/scenarios.json --base-url https://example.com/v1 --model MODEL_ID --key-env MODEL_API_KEY --out /path/to/api-runs
```

导入输出为一个 JSON 数组文件。`run-api --out` 接收目录，并写入 `sessions.json`、`results.json`、`report.html`。API 地址和模型名为占位符，真实调用需自行配置，并可能产生供应商费用；密钥通过环境变量提供，不写入研究材料。

## 5. 两张验收表

### 5.1 验收我们自己的算法与工程成果

| 能力 | 必须提交的证据 | 不接受的替代物 |
| --- | --- | --- |
| 状态更新 | 未知、冲突、人物/时间纠正的明确输入输出与来源；修复前后同条件对照 | 只显示最终回答变好，不检查真实输入；把人工标注质量算作自动抽取能力 |
| 证据检索 | 简单基线与候选方法；相关性、适用性、错误筛除和漏召回记录；失败例 | 只换一个听起来复杂的算法名；只展示少数成功截图 |
| 实验算法 | 预先规定主要指标、变量、配对与分母；按家族汇总及重采样；报告回归与成本 | 把每轮当独立样本扩大数量；看到结果后改标准 |
| 工程可靠性 | 输入与版本可追溯；失败留痕；故障注入确实生效；修复可回放；未评与无效可区分 | 运行不报错就称临床可靠；删除失败会话后给成功率 |
| 评测可信度 | 人工规则校准、分歧裁决、故障检出和误报、模拟器完整性检查 | 依赖未校准模型评分器的自信分；让被测对象看到答案或故障标签 |

BM25、状态机和家族配对统计说明系统已经使用可解释的算法机制。证明“算法改进有效”还需合理基线、受控比较和独立复测；本次原型不以代码存在替代效果证据。

### 5.2 验收我们发现平台不足的能力

| 输出 | 最低可审查内容 | 结论标准 |
| --- | --- | --- |
| 行为缺陷单 | 完整前缀、关键回答、期望行为及依据、适用机会、影响与严重度 | 可以复核确实发生了什么；不能只给一个标签 |
| 候选原因 | 算法、知识、工程、测量等可能原因；观测等级；仍未排除的解释 | 黑盒内部原因保持假设，允许混合原因和待排查 |
| 区分实验 | 同合法前缀、只改变指定因素；记录不匹配条件与重复 | 证据支持什么就写到什么程度，不从行为结果直接编造架构 |
| 修复任务 | 具体修改位置或下一步所需观测、回归集合、失败条件 | 自建系统可验证修复；黑盒平台可提出改进建议，不能宣称已修复其内部模型 |
| 比较报告 | 平台批次、两条实验轨、分项覆盖、严重错误、未评/无效、家族配对和区间 | 不混淆产品与底层模型；不以一个综合分抵消风险和覆盖缺口 |

## 6. 下一批可验收任务

以下任务是后续工作，不属于本次原型已经完成的能力。具体实现应继续遵守 v1.0 的 W01–W08 工作包和准入要求。

| 任务 | 算法工作与需要学习的知识 | 工程交付 | 完成条件 |
| --- | --- | --- | --- |
| N01 真实问题比较协议 | 实验设计、分层抽样、家族独立性、混杂控制 | 采集协议、条件清单、去标识审核记录、冻结问题与评分版本；小荷和通用平台人工试跑 | 来源与使用依据齐备；保留完整失败记录；两轨和批次不混用；由独立人员复核导入与评分证据后再扩大样本 |
| N02 自由问询执行 | 有限状态机、部分可观察任务、条件披露、模拟器偏差 | 受约束患者模拟器；动态逐轮执行；预算、停止、错误恢复和完整轨迹 | 模型自主问询；事实不漂移、不超范围披露、不见评分答案；漏问不会触发自动送答案；人工检查自然度 |
| N03 评分者校准 | 评分量表、标注者一致性、位置与长度偏差、置信区间 | 临床评分界面或文件流程、盲评、分歧裁决和冻结规则 | 临床关键项经合适人员审核；未评不自动通过；严重错误不能被平均分掩盖；报告人机与人际分歧 |
| N04 自然语言到状态的映射 | 指代、否定、时间、事件抽取、实体链接、置信校准 | 口语标注集、规则和模型基线、结构化抽取适配器、来源跨度校验 | 分别测抽取错误与状态更新错误；未知不被补成否定；纠正、家属代问、冲突有留出案例；低置信时保留未知或请求澄清 |
| N05 既有证据连接 | BM25、语义向量、混合检索、重排序、召回与适用性 | 接入原有来源和 `passage_id`，冻结快照，记录日期、人群、段落、查询和筛除原因 | 与简单基线配对；展示漏召回及错误筛除；正确引用标识不能替代结论支持检查；缺失元数据保持未知 |
| N06 完整故障库与回放 | 对照、消融、反事实、因果可识别性、评分器偏差 | 扩展 F01–F10；分别验证注入组件、目标行为与评分器反应；回放绑定实际输入 | 按 v1.0 的每类规模和误报/检出建议验收；注入后合理恢复算成功；黑盒不能借故障标签提升内部归因等级 |
| N07 一次真实模型改进 | 根据缺陷选择提示、检索或抽取策略；有数据依据时再考虑监督微调（Supervised Fine-Tuning，SFT）和偏好优化 | 真实基线、候选、冻结配置、成本记录、回归和按既有流程放行的独立复测 | 至少一次单因素改动有可复核结果，报告不改善家族、成本与回归；无效果也保留真实结论，不在测试后重新包装结果 |

优先次序为 N01、N03 与当前人工导入闭环，N04、N05 的局部算法验证，再推进 N02 与 N06 的完整会话诊断。N07 必须基于已确认的缺陷选择改动；不把训练大模型本身设为提前完成的目标。

## 7. 阶段和准入

当前四个合成家族只用于开发机制。随后扩展到 v1.0 的 24 个公开开发场景；72 个独立研究家族及其分区、封存、专家审核按基础任务书实施。已暴露案例和改写不能重新标成全新测试。

持续集成（Continuous Integration，CI）通过不改变既有 S5、S6 阶段准入。正式独立评测、受保护数据自动信任和训练导出继续受原有流程约束。本次不修改这些门禁，也不以新任务书授予放行资格。

真实问题的离线研究、标准化患者试验和真实患者使用是不同阶段。系统可以面向真实患者需求设计，但离线分数不能直接证明患者理解、获益或临床部署安全；人类使用研究需单独完成相应审核、监测、人工升级和停止机制。

本版完成定义：当前核心及其边界可运行、可审查；最新黑盒比较任务与适配方案完整；下一批工作有算法内容、工程交付和证据标准。小荷及通用模型的实际优劣，必须由后续完成采集和审核的报告给出。
