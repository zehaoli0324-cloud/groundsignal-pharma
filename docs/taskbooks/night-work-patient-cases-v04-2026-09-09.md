## 1. 今晚的唯一主目标

把 `candidate-review-clinical-semantic-revision.json` 从“结构兼容的人工/模型辅助审阅稿”推进为一条可复核的开发链：

```text
私有审阅文件
→ 官方合同验证
→ 遗留问题与阻断清单
→ 12 个候选病例选择
→ 动态病例 v0.4
→ 离线轨迹与盲评包
→ 回归、审计与交接
```

目标不是生成临床答案，也不是让病例自动获得 Gold（临床金标准）资格。任何无法从原文、审阅记录或冻结规则证明的医学判断必须保持待定。

## 2. 固定边界

1. 患者原文、映射、审阅者文件和可能含身份信息的内容只放在受控本地目录或 Library，不提交公开仓库。
2. GitHub 只保存代码、合成测试、字段规范、聚合统计、去敏错误编号和不含患者原文的报告。
3. 保持 `gold_approved=false` 与 `s6_automatic_trust=BLOCKED`；不得通过改字段、改路径或改报告绕过。
4. AI 审阅属于候选意见，不得冒充执业医师审核、双人独立人工评审或临床真值。
5. 不调用付费模型，不采集小荷健康，不发送外部消息，不导出训练数据。
6. 已暴露的 50 个候选和派生 12 个病例属于开发材料，不得标为 fresh held-out（全新留出集）。
7. 保留第一次失败、未评、未知、测量无效和不完整运行；不得只保留成功结果。
8. 不修改或覆盖 S5 历史冻结收据、既有首次观测和已发布结果。
9. 所有新代码必须有针对性测试；所有结论必须带明确分子、分母、版本与适用范围。
10. 仅在本夜间分支提交，建立草稿合并请求；夜间任务不得自行合并到 `main`。

## 4. 每小时执行协议

每一轮先读取：

1. 本任务书；
2. 最新交接文档；
3. 夜间分支最新提交和草稿合并请求；
4. `docs/handoffs/nightly-patient-cases-v04-ledger.md`（若已存在）；
5. 上一轮测试与去敏审计结果。

然后选择“尚未闭环且依赖已满足”的最高优先工作包。每轮必须完成一个可验证增量，而不是只更新状态。

每轮结束必须：

- 运行与改动直接相关的测试；
- 运行 `git diff --check` 等价检查；
- 检查新增公开文件是否含患者原文、身份信息、Library 标识、审阅文件正文或本地绝对路径；
- 提交到同一夜间分支；
- 在夜间 ledger 追加：输入提交、实际改动、测试、观察结果、未解决问题、下一轮入口；
- 更新草稿合并请求摘要；
- 若出现临床裁决、隐私不确定、证据缺失、权限或历史对象缺失，记录 blocker 并转做不依赖该 blocker 的工程任务，禁止猜测通过。

若上一轮仍在运行或目标分支产生无法解释的新提交，本轮停止写入，只做只读核验并记录并发冲突。

## 5. 工作包与验收

### N0 任务控制面与可恢复性

交付：

- 本任务书；
- 夜间 ledger；
- 草稿合并请求；
- 固定分支、基线与不允许自动合并的声明。

验收：

- 下一轮不依赖临时会话即可恢复；
- 每项数字能追溯到提交或报告；
- 没有把计划写成已完成。

### N1 私有审阅文件的官方验证

交付：

- 使用仓库 `candidate_review validate-review` 的实际结果；
- 兼容性检查与官方检查的差异报告；
- 仅包含编号和聚合数量的公开验证报告；
- 对输入文件身份使用 SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列）绑定，但不得公开原文。

验收：

- 验证命令、版本、成功/失败和错误数可复现；
- 失败不得改写为通过；
- 审阅文件不进入 Git 历史。

### N2 遗留问题与裁决队列

交付：

- C0001、C0021、隐私提示、冲突极性及高风险规则的机器可读 blocker 清单；
- 每项包含证据位置、问题类型、自动可修复性和所需人员角色；
- 可机械修复项与医学裁决项分离。

验收：

- 不自动填写医学结论；
- 不因结构合法而宣称语义正确；
- 修复后重新运行 N1。

### N3 十二病例选择

交付：

- 可复现的候选选择器或明确的冻结清单；
- 选择特征：隐私状态、事实完整性、时间/否定/纠正结构、动态问询机会、评分可写性、风险、来源家族和近重复关系；
- 12 个开发病例的去敏聚合报告；
- 未入选原因分布。

优先采用 6 个病例家族 × 2 个受控变体；若真实候选无法支持这一结构，必须报告实际可支持数量，不得补造医学事实。

验收：

- 未解决隐私或临床阻断的病例不能进入 runnable 状态；
- 同源或近重复病例不跨开发/未来独立分区；
- 选择规则在看模型回答之前固定。

### N4 动态病例 v0.4

每个病例至少包含：

- 初始可见事实；
- 问到才披露的事实；
- 未来信息；
- 未知、否定、纠正和冲突关系；
- 有限状态机（Finite State Machine，FSM，按状态与触发条件推进交互）；
- 问询触发条件、披露槽和停止条件；
- 评分机会、触发回合、响应回合与截止；
- 0/1/2 分锚点；
- 任务完成判断与严重错误判断；
- 原始证据定位及审阅状态；
- `development_exposed=true`、`clinical_gold=false`。

验收：

- 未来信息不能提前出现；
- 问句不能转成肯定事实；
- 纠正后旧值不得覆盖新值；
- 人物、时间和否定范围可审计；
- 无法完成医学裁决的病例保持不可运行。

### N5 离线执行、盲评与回归

交付：

- 对 runnable 病例生成离线会话；
- v0.3/v0.4 兼容的盲评包；
- 质量、任务完成、安全和测量有效性分开保存；
- 覆盖未来泄漏、误披露、漏披露、跨病例串联、未到达机会、服务失败和部分审评的测试；
- S5 历史收据只读核验与患者模块回归。

验收：

- 不把离线夹具表现当作真实模型成绩；
- 未评安全不得转为安全通过；
- 测量失败不从任务分母静默删除；
- 全部公开输出通过去敏扫描。

### N6 夜间收尾

交付：

- 一份回答优先的交接报告；
- 已完成、失败、阻断、测试数字和证据入口；
- 下一步只列依赖已满足的动作；
- 草稿合并请求保持未合并。

验收：

- 不夸大临床、真实用户、模型提升或独立泛化结论；
- 明确哪些工作仍需要人工临床审核或真实平台配置；
- 主线未被自动修改。

## 6. 每轮优先级

1. 先保证隐私、证据边界和可恢复性。
2. 再完成官方验证与 blocker 分类。
3. 再做 12 个病例选择和动态病例工程。
4. 再做离线轨迹、评分与回归。
5. 真实模型调用、临床 Gold、训练出口、正式 S5 准入和 S6 自动信任不属于今晚自动任务。

## 7. 成功定义

今晚成功不要求强行完成 12 个临床可运行病例。满足以下条件即为有效进展：

- 私有审阅文件得到官方、可复现的验证；
- 所有剩余问题被准确分为“机械可修复”和“需人工/临床裁决”；
- 能安全选择多少病例就冻结多少，数量不足要如实报告；
- 对已具备条件的病例形成动态合同、测试和离线产物；
- 所有失败、未知和阻断被保存；
- GitHub 上形成可审查的连续提交和草稿合并请求，但不自动合并。
