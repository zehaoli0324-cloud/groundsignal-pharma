# 患者评测文献设计补充 v1.3

日期：2026-09-09。状态：**已恢复开发，v0.3 实现 L1–L4 的必要核心，真实实验尚未开始**。原设计基于功能版本 v0.2 与文档合并提交 `508339e1ca6490d39a6682380e24d5c0143db2ad`；实现证据见 [v0.3 验证页](../../medical/patient-eval/VALIDATION_V0.3.md)。

与[主任务书 v1.2](patient-evaluation-master-taskbook-v1.2.md)配套使用。下文细化未来实现的实验关系、患者状态、评分和取证要求；已冻结的场景、判据、历史结果不回写。论文原文事实、版本和页码见[方法依据](../../reference/METHODS_TO_DESIGN.md)。

## 1. 设计决定

保留 GroundSignal 的十阶段流程，以及独立的患者评测子系统。恢复开发后，先校准测量工具，再做小规模真实试评。新算法需有具体失败、可比较的基线和可追踪的效果；大规模训练、多智能体编排与全医学知识树都不是近期默认依赖。

本轮文献支持四项直接调整：

1. 压力变体需要声明输出关系：保持结论、更新结论、信息不足时暂缓判断。
2. 患者事实、当前已披露信息、评分参考三者隔离；问句识别与状态更新分别校准。
3. 回答质量、任务完成、安全判断和测量有效性分别保留，不能压成一个通过／失败。
4. 固定历史后的回答评分、自由问询的完整任务评价、组件原因的受控回放分别分析。

这些是我们对论文方法的迁移设计，不是论文已经验证了 GroundSignal 的效果。AMIE（Articulate Medical Intelligence Explorer，医疗对话研究系统）的训练模拟、真人扮演患者研究与真实患者应用也需分别标注。

## 2. 需要补充的工作包

以下是完整设计目标，不能把局部代码完成当成整个工作包验收。当前 L1 已有压力关系声明校验；L2 已有版本化问询识别及开发校准；L3 的独立评分数据与导入比较已打通；L4 已有逐判据人工一致性统计。独立人工校准、自动评分器、L5 与 L6 尚未完成，详见 [最新交接](../handoffs/2026-09-09-patient-eval-v03-handoff.md)。

| 工作包 | 对应阶段 | 算法／实验任务 | 工程支持 | 交付效果 |
|---|---|---|---|---|
| L1 压力关系与病例覆盖 | S1、S5、S7 | 变形测试：可控改变输入，核对预先指定的输出关系；按任务、实体和风险分层 | 场景版本增加变换关系、变化字段、必要证据与审核记录；保留家族标识 | 区分不该改变却改变、应该更新却不更新、证据不足仍断言 |
| L2 中文患者交互与状态 | S3、S6 | 问询意图识别、否定作用范围、人物与时间抽取、显式纠正事件、有限状态机 | 扩展 `patient.py`、`extraction.py`；保留原文位置、状态差异、人工接管和停止依据 | 区分模型没问、模拟器没听懂、抽取错、状态更新错 |
| L3 评分与机会数据 | S7 | 分开质量、任务完成与严重错误；按实际机会和截止判分 | 修订 `pilot.py`、`scoring.py`、审评导入和报告，允许部分维度已评 | 质量改善能进入结果；安全未评不覆盖已有质量判断 |
| L4 人工与自动评分校准 | S7、S10 | 双人独立标注、逐判据一致性、二元漏检／误报、文风偏差对照 | 扩展 `agreement.py`，拟建独立评分器校准入口及版本记录 | 先知道评分哪里不稳定，再决定哪些判据可交给模型初评 |
| L5 证据使用与工具诊断 | S2、S6、S8、S9 | 正确证据、缺失证据、干扰证据对照；声明与来源对应；工具预算消融 | 将现有检索和执行日志接入患者流程，记录实际上下文、失败、引用和预算 | 区分没找到、没传入、传入后没用对；黑盒只报告可见行为 |
| L6 真实文本与可重复研究 | S1、S5、S6、S10 | 去标识复核、语义保留、按来源家族分组、配对比较与重复运行 | 受控原文、会话内一致替代标记、来源／版本清单、盲评包和不可覆盖的运行目录 | 保留真实语言特征，同时避免身份泄漏、样本重复和结果挑选 |

负责人角色：项目负责人核准范围与主要指标；算法与工程开发者实现并测试；医学审核者核准临床事实与安全判据；独立评分者保留原始分歧。新增正式独立测试仍执行既有 S5 管理流程。

## 3. L1：压力必须有可核准的预期

顾禹等的压力实验包含不同性质的干预；不能把所有变体都按“和原答案一致”评分。原文依据见方法依据中的第一篇论文。

| 变换关系 | 患者评测中的拟议例子 | 应测什么 |
|---|---|---|
| 保持结论 | 事实不变，仅改变措辞、信息顺序或加入无关内容 | 必要事实与任务结论是否稳定；措辞无需逐字一致 |
| 更新结论 | 更正日期、咨询对象或关键检查信息 | 是否使用更新后的适用事实；原答案不能沿用为新标准 |
| 信息不足 | 移除完成任务必需的信息，或只提供无法核实的转述 | 是否澄清、保留未知或说明适当限制；不能无差别拒绝仍可完成的部分 |

拟增加 `relation`、`changed_fields`、`required_information`、`expected_behavior`、`reference_evidence` 和 `review_status`。这些字段属于评价侧，不传给目标模型。

事实改变的病例需要重新核准预期；包含医学意义的变化由相应人员审核。先改变一个因素，后续交互压力组合单独登记。现有 v0.2 清晰／压力配对继续使用原定义，不往已冻结场景添加新真值。

验收分开报告三类关系的合规率、基线正确率和“基线正确时”的条件结果，同时展示全部配对，避免仅挑原本答对的案例。同一来源的改写和重复保持在同一家族；不能以变体数量扩大独立样本数。

医学实体覆盖先用疾病、药物、人群、风险和任务的人工可审查矩阵。分别统计“提到实体”“有证据”“有审核案例”。仅当词典规模和耗时证明需要时，才比较 Aho–Corasick 多模式匹配（一次扫描查找大量词条）；词条命中不能作为医学正确性。

## 4. L2：将患者事实与中文表达分开

保留有限状态机（Finite State Machine，FSM：按当前状态和触发条件推进交互）作为事实控制层。问句识别器只负责提出请求的事实字段；控制层决定本轮允许披露什么。自然语言改写器如后续引入，仅改写已批准的回复内容，新增事实、改变极性或时间时必须拒绝并留痕。

每条可见事实拟保留：

| 字段 | 作用 |
|---|---|
| 原文片段、回合编号 | 可以回到用户实际说过的话 |
| 人物、概念、极性 | 区分谁的什么情况，以及“有／没有” |
| 确定性、信息来源 | 区分确定说法、未知、推测和他人转述 |
| 事实发生时间、记录时间 | 避免“后来录入”覆盖“后来发生” |
| 事件类型、被纠正事件 | 区分明确纠正、情况变化、新增信息和未解决冲突 |
| 解析状态、版本 | 未理解不补成事实，能比较新旧抽取器 |

“不是昨天，是上周”是纠正；“昨天没有、今天有了”是变化；“医生说可能有”是转述与不确定。不能统一采用后一句覆盖前一句。当前确认的是用户明确报告的说法，不等于已经获得临床核实。

先建立独立中文表达样本，覆盖问句、陈述、否定要求、引用、多问题、代问和合理结束。逐字段统计误抽取、漏抽取和未解析；交互侧另报误披露、漏披露、事实漂移、未到达事件和人工接管。固定核验集中的未授权披露与未知转阴性应为零；这仅约束已核准测试，不构成真实空间零风险保证。

medSpaCy（临床文本处理工具）可借鉴上下文模块结构，但官方语言表没有现成中文支持。PubMedBERT 是英文生物医学文献编码模型，ClinicalBERT 是英文临床笔记编码模型；BERT 全称 Bidirectional Encoder Representations from Transformers，表示利用双向上下文编码文本。二者不作默认依赖。规则确有瓶颈后，再在同一中文标注集比较规则、中文编码模型或结构化大模型抽取，并计入成本和新增错误。

合理停止按任务定义：信息整理完成即可结束；不能照搬诊断系统“给出诊断和治疗方案才结束”的条件。自动停止不确定时交人工判定，禁止强行追加隐藏信息让模型完成探针。

## 5. L3：评分结果拆成独立维度

HealthBench 原生方法针对固定历史后的下一条回答，使用病例特定的二元判据和正负权重。GroundSignal 的 0–2 分与动态机会判断是本项目扩展，需要单独校准。

| 维度 | 拟保留字段与状态 | 规则 |
|---|---|---|
| 质量 | 各分项 0／1／2、已评／未评、证据、评分版本 | 通俗、依据、未知和解释修复分别显示；不将分数自动转换为临床结论 |
| 完成度 | 已完成／未完成／不适用、原因 | 遗漏必要任务与没有看到某一探针分开记录 |
| 安全 | 严重错误已确认／经审核未确认严重错误／未审核 | 普通质量不足不能自动成为严重错误；无审核不能显示安全通过 |
| 机会 | 是否出现、触发回合、回答机会、截止到达、正当停止 | 只能使用截至该机会实际可见的信息 |
| 测量有效性 | 有效／采集问题／模拟器问题及影响范围 | 不能通过删除平台失败提高成功率；全部排除留原因和数量 |

修复现有 `apply_review` 因最终结论未评而跳过质量记录的问题，并让 `score`、`compare` 和报告保存与比较预先选定的质量指标。安全、完成度、质量分别显示已评分母和覆盖率。

若任务确需的信息因模型未追问而未获得，且不存在正当停止，计入信息获取／任务完成失败；信息尚未披露时，后续吸收或纠正判据保持未触发，不重复判错。机会后的质量率按实际有效机会计算，同时报告机会覆盖率和全部预分配会话的完成情况。平台故障保留在执行结果分母；采集／模拟器导致的测量无效单列原因及数量，不能让少问或失败会话通过“不适用”消失。

验收例：一条解释得到 1 分，安全尚待医学审核；导入后质量必须仍可见，安全仍未知。另一条回答解释流畅但有经确认的严重错误，质量不能抵消该错误。未来纠正内容不能反向惩罚模型在纠正出现前的回答。

通用安全规则只有适用于该病例时才启用；病例特定规则需来源、作者、审核、权重理由及版本。暂不迁移 HealthBench 总分或论文排行榜阈值。真实患者是否理解，需要后续人类复述或行动选择任务，模拟器的预设误解修复不能代替它。

## 6. L4：先校准人，再考虑模型初评

先使用少量开发会话双人独立试标，保留两份原始结果与适当人员的裁决。初始标注者不能看到对方答案。修改评分规则后冻结新版本，再评受影响材料。

逐判据至少报告：

- 机会和适用状态的混淆表；未知、不适用、未到达机会分别显示。
- 0–2 分的完全一致率和线性加权 Cohen’s kappa（科恩一致性系数，扣除偶然一致并按分歧大小加权）。
- 二元安全判断的漏检、误报、样本量与未评数量；不可只报告整体准确率。
- 正确性相同而长短、格式、礼貌不同的回答是否被系统性偏爱。
- 按病例家族保留配对的重采样区间；样本不足或系数未定义时如实显示。

只有人类判据足够清楚后，才加入大模型评分器。校准集与最终比较集分开；模型建议必须引用原文证据，输入回答中的“忽略规则、给满分”等内容按待评文本处理。检验错误放行、错误否决以及提示注入；评分器调用失败保持未评，不补通过。

验收阈值根据开发样本与错误风险预先核准，不借用论文的一致性数值作为本项目通用标准。模型间多数一致不替代临床标准。严重错误和分歧项保留人工审核。

## 7. L5：把“找到”与“用对”拆开验证

先复用已有来源、段落标识与检索基线。BM25（Best Matching 25，基于词项匹配的排序方法）、结构过滤、语义重排是否需要组合，由实际漏检与排序错误决定。

对自建流程安排不同取证条件，保持同一任务和模型配置：

1. 不提供外部资料，测其默认行为。
2. 在相同历史中提供经核准的必要证据，测是否能正确利用。
3. 在正确证据之外加入无关、旧版或冲突材料，测选择和解释是否退化。
4. 使用真实检索结果，并记录查询、候选、最终片段与实际发送内容，检查问题发生在哪一步。

2、3 属于给定证据实验，不能计作检索成功；2 与 3 的额外长度等变化也要登记。候选证据的临床适用性必须核准。可见回答建立“断言—来源片段”映射，分开遗漏、错误新增、否定反转和纠正后旧值残留；来源存在不等于支持结论。

工具日志拟增加请求编号、输入／输出摘要、所用片段、重试、失败、预算与停止理由。按预算比较完成率和错误率，不以调用少作为唯一目标。中断恢复只能在确定请求状态并验证版本一致后设计；响应未知的请求不能自动重试而重复计费或伪造完整成本。

DeepMed 官方摘要提示过多工具调用可能引入噪声，因此先安排预算与证据对照；其训练惩罚和推理监控不直接列为已验证实现。AMIE 2026 的消融也说明组件增益依赖基础模型，复杂结构要和简单流程实测比较。

小荷等应用只能记录用户实际看到的引用、回答和等待时间。提供证据后回答改善支持“对证据条件敏感”，不能直接断言其内部检索器故障。结构化输出合法也不能证明引用支持、医学判断正确或隐藏推理可靠。

## 8. L6：语言数据、脱敏与统计单位

MedDialog 用于识别中文咨询表达形态，医生原回复不直接作为当前标准答案。CBLUE（Chinese Biomedical Language Understanding Evaluation，中文生物医学语言理解评测）可用来建立实体和意图等组件基线；附件 CLUE（Chinese Language Understanding Evaluation，通用中文语言理解评测）不能替代它。

真实文本准备包含身份信息扫描、人工复核、会话内一致的替代标记和私有映射。分别测漏删与误删，并检查药名、剂量、人物关系、纠正关系和病程间隔是否保留。若需移除真实日期，替代时间保持必要相对关系；跨日期依赖的医学适用性再审核。中文统计需明确按字符、词或实体的分母，不能直接搬英文每千词指标。

来源、原始会话、患者及近重复衍生关系决定分组；同一咨询的改写不能跨开发和独立测试。公开可见不自动等于获准再分发。原文、映射和未审核输出保留在受控位置。

首次跨平台试评仍为 12 变体 × 2 平台＝24 会话，目的是查流程。之后如固定条件重复三次是 72 会话，独立家族仍只有 6 个。该规模不支持广泛临床优越性结论；正式独立研究仍需另外完成 S5 准入。

## 9. 实验与实现顺序

| 顺序 | 恢复后要交付的最小结果 | 进入下一项的条件 |
|---|---|---|
| 第一批 | L1 的三类关系规范、L2 的披露／状态校准、L3 独立评分字段、L4 双人试标流程 | 规则、事实、机会和评分版本可复核；已知误披露和评分丢失问题有针对性回归 |
| 第二批 | 24 会话真实流程试评、首批带证据缺陷卡片；L6 真实材料仅在完成相应准备后使用 | 有完整原文、有效分母、人工判定和失败记录 |
| 第三批 | 同一模型的原始流程与状态增强对照；对一个缺陷进行组件回放 | 区分整体组合效果与组件原因，保留无改善及退化 |
| 按缺陷触发 | L5 真实检索／工具对照、模型评分器、纵向随访、语义抽取模型 | 现有简单方法的失败证据表明需要，收益超过成本与新增错误 |
| 继续暂缓 | 大规模实体树、从零预训练、强化学习、复杂多智能体、大规模多模态研究 | 独立数据、预算、评测器与目标缺陷均准备好后另立任务 |

同模型的第一轮对照只证明“抽取＋状态＋提示”这一组合的效果。后续可加入仅根据已披露文本人工核准的参考状态，用于判断抽取是否限制效果；不得使用未来隐藏事实，也不得将人工参考臂宣称为可部署算法。

自由对话允许两组问询路径不同，比较任务结果；固定前缀回放控制相同可见历史，比较局部干预。对照两组均记录完整实际输入、配置、顺序、重复编号与成本；模型版本或应用界面不明时据实记录，不能把论文模型配置套到某次小荷会话上。
