# 复杂临床推理、主动取证与错误归因工程计划 v1.0

日期：2026-09-12。项目：GroundSignal Pharma。用户已要求提交 GitHub、开始实施并每小时迭代。

## 目标与归属

让评测回答三个问题：模型为什么选择这个问题或检查？新证据怎样改变病因判断？错误源于取证策略、证据理解、假设整合，还是工具与上下文工程？

主模块放在 **S8 缺陷诊断与能力假设**，新增“复杂临床推理与主动取证归因”工作线。它复用 S5 案例准入与配对、S6 动态执行、S7 过程评分，进入 S9 最小干预和 S10 独立复测。保留原阶段与 C1–C8 编号；临床推理子维度暂作为独立扩展字段，不冒充现有 C3 事实更新能力。

| 阶段 | 新增交付 | 连接方式 |
| --- | --- | --- |
| S5 | 病例标准审查、可见输入/模拟世界/评分标准分离、配对差异清单 | 向 S6 提供允许披露的事实与动作；向 S7 提供按证据状态定义的判据 |
| S6 | 自主问询、记录查询、工具失败与恢复、固定前缀回放 | 每次记录动作、实际返回、实际投递、模型可见上下文与版本 |
| S7 | 每轮病因假设、取证价值、更新合理性、停止/转交、安全 | 保留未评；区分临床表现、工程事件与测量质量 |
| S8 | 竞争解释、区分实验、单组件与组合干预验证 | 输出证据支持范围、未排除原因和下一实验 |
| S9/S10 | 最小修复、跨家族迁移、冻结后复测 | 目标改善、安全/过度拒答/成本退化分别报告 |

首个示范：**肾功能恶化的多病因鉴别与主动取证**。第二家族：**炎症背景下贫血机制鉴别**。当前仅为合成开发材料，临床专家批准和真实模型结果均不存在。

## 临床标准与事实世界

病例标准初审见 `medical/patient-eval/clinical-reasoning-v1/CLINICAL_REVIEW.md`。患者病因与“模型错误的原因”分别存储；模拟世界里作者设定的病因不自动成为可从可见证据推出的结论。

肾功能家族保留：近期变化未确认、容量与用药共同可能、出现梗阻客观证据后调整排序等状态。不要预设三者互斥。先确认病程证据，再评价原因；不强制第一轮猜中最终披露的因素。首轮草稿不预填唯一确诊病因。

贫血家族保留：低铁不是单独定因依据；炎症背景与混合机制需评估。哪些进一步资料具有鉴别价值、何时能降低不确定性，交临床审核，而不是凭人工写的流程图自动给满分。

每个病例分三面：`opening` 为模型初始可见内容；`world` 为模拟器事实和动作回包；`evaluation` 为评分端标准。输出适配器不得接收整个病例对象。评分只使用截止点前真正投递的资料。开发端结构化动作不宣称已经解决自由口语意图识别。

## 过程评分

| 子维度 | 要保存的证据 | 常见错误 |
| --- | --- | --- |
| 病因假设与证据关系 | 当前假设、简短支持/反对理由、可见证据编号 | 过早收束、漏掉关键解释、把相关性当已证明因果 |
| 主动取证 | 实际问题或工具参数、要区分的假设、返回信息 | 无价值重复、漏问改变决策的条件、追问拖延必要转交 |
| 证据解释与整合 | 报告原文、简短解释、更新前后判断 | 单指标捷径、把没检查当阴性、忽略相互作用 |
| 更新和停止 | 证据到达时间、假设变化、后续行动 | 锚定、过度翻转、证据充分仍无效搜索 |
| 工程与恢复 | 调用/响应/投递/消息快照、故障分类 | 超时伪成功、报告错配、工具结果漏传 |

只要求可观察的简短决策摘要、行动与证据引用，不要求私有思维链，不把模型自述当内部机制证据。过程记录会改变任务，应在对照两组使用相同输出要求，并用自然对话轨验证迁移。

质量 0/1/2、任务是否完成、严重错误、评分机会分别存储。未评不得变成通过、零分或安全。未获取的信息不能被用于指责模型“忽略”；但若该信息有明确可行且必要的获取路径，可以评价问询/工具策略。严重性由临床裁决，不把每个推理偏差自动算严重错误。

问询价值先用专家核准的定性锚点（是否改变紧迫性、区分病因或改变下一步），不伪造真实疾病先验或精确信息增益。允许多条合理路径及正当提前转交。

## 归因实验矩阵

1. 完整资料但无病因提示：排除缺少问询作为全部解释，不等于测到纯粹推理能力。
2. 同一前缀替换一个取证动作：只提供原世界中确实可取得的回答；记录这个信息干预及后续分叉。
3. 固定原始报告的证据解释任务：检查知识/理解，不能用简化任务通过直接宣布复杂整合正常。
4. 实际工具返回与模型输入逐项核对：验证报告身份、版本、时间、内容及投递边界。
5. 单组件修复和匹配回放：相同病例、模型、政策、预算、前缀、评分版本；保存首次失败和恢复，未改变无关组件。
6. 问询策略×工具传递的四组组合干预：原/替换策略与原/修复投递，区分共同瓶颈、替代路径和无法识别。
7. 同事实的新会话与已有判断历史比较：明确历史、顺序和篇幅的残余混杂，不直接叫内部锚定机制已证实。

故障确实发生、故障是否导致行为失败、评分器是否检出是三项独立结果。模型恢复成功是成功；故障标签不可进入模型或盲评分者输入。对同一根因构造至少两个不同错误表现，且对同一表面错误构造不同故障来源，防止归因器按症状标签猜答案。修复有效不自动证明唯一根因。

每次区分实验输出：观察、竞争解释、真实改变、匹配项、残余差异、逐次结果、结论上限、未排除原因、下一实验。证据等级为行为观察、干预支持、受控组件证据或无法区分；黑盒永不自动升级为内部已证实。

## 工作包与顺序

| 编号 | 工作包 | 依赖 | 验收 |
| --- | --- | --- | --- |
| CR00 | 基线、范围、来源与旧资产初审 | 无 | 固定输入提交与文件摘要；六项缺口有处置记录 |
| CR01 | 两家族临床草稿与审核单 | CR00 | 病程证据和病因真值分开；专家待评明确，不能自批准 |
| CR02 | 可见输入投影、配对验证、最小动作环境 | CR01 草稿 | 只改变指定因素；未来事实隔离；首个取证/投递轨迹，临床仍未评 |
| CR03 | 自然问询适配与动态循环 | CR02 | 合法多路径、问不到/不支持/停止分开；相同世界可重复回放 |
| CR04 | 逐轮评分与独立评审接入 | CR03 + 相关审计问题处置 | 未评、身份重复、版本变化、机会边界负例均不误通过 |
| CR05 | 工具与上下文实际投递检查器 | CR02/CR03 | 干净、丢失、错配、恢复、虚假恢复与实际成功恢复均有证据 |
| CR06 | 检索/映射检查器与组合归因 | CR05 | 症状同因异/异症同因、四组干预；不把提示提升当唯一根因 |
| CR07 | 肾功能完整示范与贫血迁移 | CR04/CR06 | 两家族使用同一接口，原始轨迹到缺陷报告可重算 |
| CR08 | 真实模型试评与临床复核 | 可用模型配置/预算、相应用途准入、临床标准审核 | 多次配对运行、独立评分、失败分析、一次受控修复；未经实际执行不得填结果 |
| CR09 | 冻结、独立复测与交接 | CR07；研究结论另依 CR08 | 他人复现、目标/退化/安全/成本报告，判断工程与研究各自完成度 |

工程校准初始目标：每个新增归因检查器至少 10 组干净/故障配对，覆盖两家族并包含故障被正确恢复、同症不同因、混合原因；这是开发覆盖目标，不是临床性能阈值。统计单位为独立病例家族/病例；多轮和重复不当独立患者。只有两个家族时不输出貌似精确的跨病种置信结论。后续样本量与真实模型重复数在先导方差和预算明确后冻结，不能看结果选择次数。

## 每小时执行规则

每次读取本计划、`PROGRESS.json`、最新分支提交和 PR #23 的审计进度；选第一个依赖满足且未完成的工作包，完成一个有实质代码/资料/证据的批次。不能只写心跳或重复计划。

使用独立 checkout，核对远端头，禁止覆盖他人修改或强推；新模块默认只写本工作分支。若分支已合并，先核实新的集成基线并开下一个明确依赖的分支。一次只一个写入者；并发占用时不执行同一批任务。开始前检查有无同批次成果，避免重复提交。

运行与变更直接相关的正负测试，保留首次失败、修复和最后结果。更新进度的已实现/已验证/真实模型/临床审核四种状态；以 GitHub 提交作为持久交接。使用随机合成记录或公开获准开发材料；不导出隐藏研究集、原始患者数据、密钥或未批准训练行。

先完成可授权的离线工程；没有真实模型配置/预算、临床审核或正式准入时，记录具体阻塞，继续其他依赖满足的工作包。全部可执行工程完成而仅剩外部输入时，暂停自动任务并报告缺项；全部工作完成也暂停，避免空转。不能借“持续完成”虚构医生批准、独立评审或模型调用。用户本轮重新启用此工作线，替代旧每小时任务的暂停状态；其他项目的任务不改。

每轮中文报告：完成项、测试范围与结果、提交号、病例/模型/专家实际状态、剩余问题、下一批。付费模型调用须有明确可用配置及预算，不因代码入口存在而默认执行。

## 完成定义

工程完成：两家族可动态执行、评分可追溯、工具/上下文/检索等归因有实际检查器、组合干预可回放、未评分不能通过，且他人能复现。

研究完成：临床标准获核准，真实模型数据与独立评分完成，因果结论受证据约束，修复与独立复测均有原始记录。代码合并、合成故障定位或历史单次模型回答不能替代这些证据。
