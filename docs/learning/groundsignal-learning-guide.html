1. 先认识正在使用的算法

方法 通俗解释与项目用途 当前边界
FSM：Finite State Machine，有限状态机 像一份有条件的问诊剧本：问题命中某项信息才披露，满足前提才触发纠正或压力事件。 已实现确定性的患者状态与事件控制；不是训练出来的患者模型。
Unicode：统一字符编码；NFKC：Normalization Form Compatibility Composition，兼容分解后组合的规范化 先统一部分字符写法，例如全角字母，再匹配问题。否定与纠正另靠明确规则识别。 已实现有限中文规则；规范化不会自动理解语义，也可能改变字符表现，因此原文必须保留。
Character n-gram，连续字符片段；Jaccard，相似集合交并比 把患者话语切成连续三个字，计算“共同片段数÷全部不同片段数”，筛出值得人工检查的相似候选。 本轮已实现候选间比较；排除医生模板。相似不证明同一患者，没有匹配也不证明测试集独立。
BM25：Best Matching 25，词频相关性排序 综合词语在文档中的频率、稀有程度和文档长度，为证据排序。 自有组件已实现，并先过滤日期和适用人群；词面相关不代表医学依据充分。
Paired design，配对实验 同一场景与模型配置分别运行原方案和改进方案，比较差值，减少病例差异的干扰。 自动脚本目前只接合成开发场景，随机安排“原对话／增加可见事实记录”。两组路径可能不同，测的是整套干预效果。
Bootstrap，自助重采样；CI：Confidence Interval，置信区间 从已观测病例家族中反复有放回抽样，观察平均改进值的不确定性。 已实现按家族等权统计；病例少时区间仍不可靠，不能把同一病例多轮当成大量独立样本。
Weighted Cohen’s kappa，加权科恩一致性系数 比较两人对同一回答的评分，扣除按评分比例可能出现的偶然一致，并区分轻微与较大分歧。 已实现按判据统计。两人一致可能是一起判断错；类别过于单一时系数可能无法定义。

这些概念可分别核对有限自动机讲义、Unicode 规范、词频排序说明、重采样说明与加权一致性说明。项目自己实现了相应的小型算法，不代表使用了这些页面的软件库。

2. 为什么还需要工程

Schema，数据结构约定，规定每条记录必须有什么字段、证据指向哪轮。未知、否定、冲突要分开，空评分不能自动变成零分。Provenance，来源与加工记录，说明数据从哪里来、经过什么处理、谁复核过。

SHA-256：Secure Hash Algorithm 256-bit，256 位安全散列算法，为文件或固定格式内容计算“指纹”，帮助发现版本变化；它证明不了医学正确性，也不是加密或匿名化。标准说明

工程里的 CI：Continuous Integration，持续集成，指修改代码后自动运行检查；它与统计中的置信区间只是缩写相同。我们合并的是实际通过检查的那次提交，不能拿旧提交的绿灯替代新提交。GitHub 说明

API：Application Programming Interface，应用程序接口，是程序向模型服务发送消息、接收回答的约定。现有适配器限制超时与重试次数，记录每次失败、可见输入及返回用量；未知开销不填成零。日志用于排查我们是否漏传消息，不能冒充第三方内部日志。

第五阶段的历史冻结材料按原版本核对；程序通过不会自动取得专家标准答案资格。本轮患者原文与替换映射留在本地审阅，公共报告只输出受限统计。隐私规则提供复核线索，零命中不代表已经脱敏完成。

3. 专业数据怎么变成测试题

本轮工具把来源对话变成待审事实卡：保留原话、来源轮次、标注范围，以及否定、未知、纠正等线索。历史医生回答不能直接当标准答案；患者问“是不是某种病”也不能自动登记为已经患病。后续才出现的信息不能偷偷补进最初提问。

已实现的是草稿生成、范围核对、隐私线索与相似度审计；尚需人工确认事实主体、时间、否定范围和披露规则，再做独立医学评分。两位真实评审的意见不能由程序代填。

本轮 50 段候选中，765 个标注提案有 745 个范围对齐、20 个不匹配；这只验证位置，不验证医学结论。旧抽取器仅产生 1 条观测、留下 842 个未解析片段，说明规则覆盖需要补足；它们不是独立标注下的错误率。先测清处理器的偏差，再评价模型，才能避免把题目处理失败算到模型头上。

5. 模型训练这些词是什么关系

Pretraining，预训练，先从大规模数据学习基础模式；常见语言模型通过预测下一个 token（文本片段）学习。Post-training，后训练，在预训练之后继续优化行为，不是一种固定算法。预训练与微调入门

Fine-tuning，微调，是在已有模型参数上继续学习特定任务。监督微调和偏好优化/强化学习是常见的后训练做法；每个模型不一定都经历所有步骤。

SFT：Supervised Fine-Tuning，监督微调，用输入与示范回答教模型怎么答。RL：Reinforcement Learning，强化学习，利用奖励学习行动策略。DPO：Direct Preference Optimization，直接偏好优化，用同一问题的较好／较差回答更新模型；原始方法不需要另训显式奖励模型，也不等同于在线强化学习。监督微调、强化学习框架、直接偏好优化

RLHF：Reinforcement Learning from Human Feedback，人类反馈强化学习，用人类反馈构造奖励，再优化模型行为。奖励若只偏爱“像医生的文风”，也可能鼓励流畅但错误的回答；可靠评分是训练的前提。人类反馈强化学习说明

PEFT：Parameter-Efficient Fine-Tuning，参数高效微调，关注“少更新哪些参数”；LoRA：Low-Rank Adaptation，低秩适配，是其中一种方法，用小矩阵表示权重增量。它可以与监督微调或偏好优化结合，二者不是同一层面的分类。方法说明

本项目当前不训练模型。 检索把资料找出来供回答时参考，状态增强把已有信息整理后加入输入，都不因此改变模型权重。先获得可信错误样本与独立复测集，才有理由决定以后是否训练。

两道起步题与答案

集合题：A={甲乙丙,乙丙丁}，B={甲乙丙,乙丙戊}。交集 1 项，并集 3 项，Jaccard=1/3。它只能比较片段，不能判断医学含义相同。

事实题：“没有发热”可作为阴性表达提案；“没有问过是否发热”只说明没问，发热状态仍未知。先标否定作用的范围，再讨论是否更新患者状态。
