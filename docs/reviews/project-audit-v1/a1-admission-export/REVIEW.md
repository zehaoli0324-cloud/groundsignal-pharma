## 连接审查结论

1. **外部来源导入与临床准入分开。** `source_intake.py`绑定原始文件字节和许可文件，输出只能位于本地忽略目录；导入结果明确标为来源材料、临床未核验、非独立留出集。结构可用不等于病例已获准入。后续候选隐私与正式病例转换仍需审查。
2. **生成政策与认证政策分开。** `s5_trust_policy_v071.py`及v0.9.1包装层生成来源登记；导出共享实现使用固定登记摘要、路径、源文件字节及载荷身份重新核对。政策生成函数没有自行获得导出授权。此处为代码审查与局部认证测试，不是本轮完整登记重建/认证通过。
3. **数据分区检查确实在导出函数调用链中。** 批准候选才进入`training_partition`；基准病例须匹配外部来源与物化载荷；`heldout`和`regression`被拒绝。新鲜数据编写准入、临床准入与开发数据导出是不同条件，不能用一个PASS替代全部条件。本批未跑真实或已批准整批导出。
4. **来源安全不能代替回答绑定。** 已认证的是病例与来源；随后`find_run`选择的回答仍需自己的编号、病例、模型、快照核对。A1-008发生在这一连接处。
5. **输出缺少整批提交保障。** 命令先写两个数据文件，再查询信任根状态并保存清单。即使前置检查严格，也还需要防覆盖、写入失败隔离和输出清单摘要。A1-009直接证明了底层写入风险；后续应在合成批次中验证完整提交顺序。
6. **冻结状态必须一致派生。** `evaluate_admission`先累积失败，再单独计算`allowed`，因此可出现互相矛盾的字段。现有`check_s5_v10_fresh_admission.py`根据`guard_gate`返回失败；历史回执验证器也先拒绝当前证明/控制面失败。本批没有把字段缺陷夸大为临床或S6已被放行。

训练候选的`approved`来自调用者提供的审阅文件；现有结构允许`reviewed_by`为空。其人工真实性与批准内容绑定是待明确的验收合同，不能把程序接纳当独立人工审阅。本批没有凭此额外宣称认证绕过漏洞。
