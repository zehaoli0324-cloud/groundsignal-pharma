# 独立审核工作台 v0.1 交接

用户批准开始搭建本地审核界面。本次只新增人工审核辅助工具，不执行或准入真实来源病例。

## 交付

- 自包含离线 HTML（HyperText Markup Language，网页文件）：`medical/patient-eval/console-v0.1.html`。内置一例完全合成记录，无患者原文。
- 来源导入、清空既有评审、事实/隐私/规则表单、证据字符片段、范围筛选、草稿导出与续填。
- 协调者逐字段比较与备注；不自动合并，不产生语义一致率。
- 机会计划和自述资格/独立性/利益冲突交接；这些是无签名草案，不是运行观察、临床签字或授权准入。
- 原有审核合同和正式 `validate-review` / `compare-reviews` 入口保持不变。新增交接验证器不提高信任级别。

## 实测

- 新增 Python 测试：12/12，其中一项调用 Node 运行10项纯状态逻辑检查，并把浏览器逻辑导出的草稿交给原有 Python 验证器，结果通过。
- 患者模块：265/265。
- S5 历史收据只读测试：14/14。
- JavaScript 语法检查通过；HTML 标识唯一、无外部脚本/图片/样式链接；内容安全策略禁止网络连接。
- 合成恶意脚本闭合字符串被转义；来源篡改、准入字段升级、异源或同编号双评、机会漏行/重复行均有针对性检查。
- 未做实际浏览器点击、下载与视觉检查。页面可交付人工试用，但不能据此宣称端到端浏览器体验已验收。

## 已处理与保留的局限

初次创建工作树时本地缺少夜间远端最终提交对象；先确认本地文档提交与远端最终提交文件树相同，再常规获取远端对象并从 `15410abe9f6ffd9afecef15ed4ed7210a5e82e1c` 新建交付分支。未重写夜间历史或主线。

实现检查中避免了载入证据时自动改写原片段，并补充“保存未完成草稿”，避免表单尚未完整时无法保留工作。上述调整后再运行全部测试。

第一版没有强身份隔离、数字签名或临床授权核验。评审者编号为自述；需协调者分别分发文件以保障初评独立。前端文件和开发测试不能代替临床专家审核。

全部新增自动化测试仅使用合成数据。未读取私有病例内容；未导出训练数据；未调用付费模型、真实模型平台或真实病例执行器。未修改 N1–N6 历史产物、冻结清单或任何病例准入字段。v0.4 的临床可运行0/12、运行机会映射0/57、S6自动信任阻断均不变。

## 下一步

由用户先用合成示例试填与导出，确认表单可读性；随后在受控环境导入兼容来源包，向两位独立评审者分别分发。收齐初评与临床裁决后，由授权负责人决定是否允许重新运行现有准入链。本次不合并夜间分支，不将工作台声明当作准入收据。
