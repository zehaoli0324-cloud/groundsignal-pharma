# 核心架构与建设顺序

2026-09-13 更新：以下实现表描述现有核心；最新建设主线已改为脑卒中，按 [完整 Hermes 任务清单](taskbooks/clinical-benchmark-hermes-tasks-v0.1.md) 执行，AP07 作为方法参考。

## 当前执行链路

题库加载与摘要验证 → 每题独立会话 → 被测模型响应 → 受控患者披露 → 原始日志与状态记录 → 回放完整性校验 → 当轮评审窗口与人工裁定。

| 部件 | 实现入口 | 责任与边界 |
|---|---|---|
| 病例与患者事实 | `benchmark/medical-dialogue-v1/`；`scripts/medical_dialogue_bench/assets.py` | 固定事实、事件前提和可见信息；隐藏题卡不进入被测模型提示 |
| 患者交互 | `scripts/patient_eval/patient.py`、`patient_intent.py` | 根据模型实际追问匹配披露；事件受前提约束；未匹配合理问法应归环境问题 |
| 会话运行 | `scripts/medical_dialogue_bench/runtime.py`、`client.py` | 独立上下文、预算、请求日志、结果与患者状态；不凭缺失日志恢复未知请求 |
| 工程参考策略 | `scripts/medical_dialogue_bench/oracle.py` | 按作者问题与回答走通链路；不能产生医学金标准 |
| 逐轮评审 | `scripts/patient_eval/app_pilot.py` | 窗口、已披露事实、判据、证据引用、未评状态与双评差异 |
| 完整性校验 | `scripts/medical_dialogue_bench/verifier.py` | 核对输入、日志、回放及评审绑定；不自动证明医学正确性 |
| 临床 Oracle | `research/ap07-oracle-draft-v1/`；`docs/AP07_NEXT_TASK.md` | 只有草稿。需独立审核条件、可接受路线、危险边界、严重性和新信息更新规则 |
| 难度与压力轨道 | `scripts/benchmark_checks/`；`benchmark/multiturn-factors-v1/` | 结构与分支验收已存在；语义难度、医学适用性、真实模型区分度仍待验证 |

## 必须分开的契约

1. **患者状态**：病情事实、患者是否知道、允许披露、预声明更正。只能沿合法事件改变，不能为逼模型犯错临时改病情。
2. **临床判据**：从当轮可见信息独立推出适用判据，声明允许路线、不可接受动作与证据。不能从作者回答标签反推评分项。
3. **模拟器与测量有效性**：问法漏匹配、非法跳转、终止、预算耗尽、未观察到等独立记录；不能统统归为模型医学失败。
4. **评审与裁定**：A/B 原始记录分别保留；争议裁定另存；历史危险建议及后续纠正可同时成立。

新临床 Oracle 后续独立放在 `clinical_oracle/stroke-v0.1/`，先形成脑卒中节点草稿与评分细则，再审核医学适用性。AP07 的接口经验可复用，医学规则不能跨病例照搬。

## 建设顺序

出题按 [专用清单](taskbooks/question-authoring-hermes-v0.1.md) 先建立决策功能/交接错误地图与患者阶段覆盖矩阵，再制作基线场景和节点判据、实验分组与压力实例。决策功能编号 D01–D12 与场景对话状态分别记录，不能混为固定问诊顺序。

先完成脑卒中参考家族的决策链、失败假设、受控实验、事实与节点草稿、评分细则及来源适用性审核材料，再取得真实临床审核和独立评分。工程准备可同步推进；按新任务清单接入独立适配器、受控分支及冻结的小批量重复试测。

常规咨询保留模糊表达、信息杂糅与较低风险对照。高风险决策压力题重点测过早安心、忽略关键事实、无谓拖延、迎合危险偏好、信息更新失败、未知用药条件下过度具体建议；需临床审核后才固化具体医疗判错规则。

同时设计“只改变临床关键条件”的配对和“只改变无关表述”的配对。公开开发题不能成为未见过的正式测试集；新模型开发与正式未曝光测试分开记录。
