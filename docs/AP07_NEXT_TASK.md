状态：待执行。当前输入是公开开发草稿，`clinical_approval=false`。任务完成必须有真实证据与评审记录，不能由作者或编码助手代签。

## 目标与顺序

先把“在什么可见条件下判什么”审清楚，再让 A/B 独立评回答。工程能运行、判据医学适用、评审可重复、题目能暴露危险错误是四个不同验收项。

第一批只做 AP07 一个完整家族，不扩题、不发布模型排名。常规咨询与高风险决策压力的总体设计见 [proposal](taskbooks/clinical-oracle-pressure-pilot-v1.md)。

## P1：补全节点与医学适用条件

每个节点必须包含以下字段：

| 内容 | 必须回答的问题 |
|---|---|
| 身份与版本 | node_id、case_version、rules_version、更新时间是什么？ |
| 可见前提 | 哪些事实必须已实际披露？未知、否定、更正和冲突怎样表示？哪些节点可并存？ |
| 适用范围 | 人群、场景、地区、严重程度、排除条件是什么？从来源到本病例的映射是否成立？ |
| 可接受路线 | 哪些追问或处置可接受？是否允许先行动并同时确认执行信息？不能只认可一种措辞和固定顺序 |
| 危险边界 | 哪个具体行为构成何种错误？时机与严重性依据是什么？哪些只是沟通不足？ |
| 更新与历史 | 哪些新信息改变处置？合理修正怎样记？早先错误如何保留并防重复累计？ |
| 引用与审核 | 原始来源、版本/核对日期、段落定位、适用性判断、作者推导和待审项分别是什么？ |
| 测量合同 | 何时不适用、无法判断、未观察到、环境无效？终止与临床判分是否分开？ |

来源更新核验与具体医学审查由具备相关能力的实际审核者完成，记录审核者身份/角色、能力范围、版本、结论、理由与时间。不能只凭网页链接存在就标通过，也不能把地区路径从一个国家直接照搬到另一个国家。

**P1 完成条件**：关键适用条件、行动边界及严重性没有未解决的阻断项；临床规则与作者设计规则有明确区分；审核结论真实填写。若仍阻断，可继续工程准备，但不启动把这些规则视为已认可的 A/B 临床评分。

## P2：重建回答样本与分阶段盲评包

每个关键判据至少有合理路线样本、明确越界样本及边界/证据不足样本；另有合理替代问法、相关追问与无谓拖延对照、同理执行建议与危险让步对照、先错后改时序样本。样本按决策机制覆盖，不靠堆罕见病和术语。

不得为了让坏样本失败而临时改变判据。样本作者期望和严重性猜测放在 author-only 开发材料，不能当独立金标签。

分发器、评分行生成器与测试须覆盖：

1. 节点跳过、节点并存、事实更正、信息不足和不可达窗口。
2. 合理回答能通过；同义改写不因关键词不同被判失败。
3. 作者期望删除/打乱后，评分项的适用性与枚举不变。
4. 阶段一包完全没有阶段二样本、后续事实、作者标签、blind-map 或可反推出答案的名称；ZIP 内部也检查。
5. A/B 分别随机化或分配盲编号，映射由管理员保管；公开开发样本的既往曝光与评审者是否为作者必须记录，不能承诺无法实现的完全盲法。
6. 阶段二解锁绑定 A/B 已封存的阶段一记录摘要；旧记录不得改写，错误与纠正分开登记。

**P2 完成条件**：构建输入、脚本与产物摘要可追溯；上述边界检查有可复核证据；临床严重性未获审的内容仍未知。

## P3：A/B 真实独立填写与争议裁定

A/B 在同一冻结规则版本上独立填写，不看对方评分及作者期望。每条记录至少含 reviewer_id/role、case/sample/window/criterion ID、版本与摘要、适用性判断、pass/fail/insufficient/not_applicable/unassessed、严重性（未知为 null）、当轮证据、理由和时间。

原始 A/B 记录只追加版本，不互相覆盖。阶段一分别封存后才释放阶段二。争议表引用双方原始行，并由实际裁定者说明依据、结论及是否导致规则修订。规则若修订影响既有判断，生成新版本重评，不覆写旧结果。

**P3 完成条件**：有两份真实独立记录和独立性/曝光声明；关键争议有处理状态；所有未评、缺失与无法判断项保留。没有审核者时，准确交付待填包与阻断状态，不能合成两个人类评审。

## P4：最小 Oracle 接口与联合试测

在获审节点合同上实现 `visible_state -> applicable_criteria`、证据窗口绑定、独立评分导入及危险事件归并。停止规则与临床判据分开，适配器不读取 author-only。遇到语义不确定进入复核，不用硬匹配自动宣布医学错误。

先用独立编写的固定回答做评测器检查，再冻结新的真实咨询试测病例与设置。既有 AP07 公开校准样本不能冒充未曝光测试。

报告至少分别列出：有效/无效/未观察窗口、双评覆盖与分歧、可共同判定项目的一致性及分母、未决争议、独立裁定后参考的来源、危险事件与后续纠正、常规咨询价值和过度分诊。作者期望一致率只可标为开发对照。

禁止把作者标签对照写成评分准确率；禁止把 A/B 一致率、裁定共识或空表数量写成 Oracle 准确率。若要评估评分器准确性，另建未用于调规则的独立参考集，声明参考形成过程、独立性、分母、不确定性与适用范围。

## 交付清单

- 审核过的完整节点表、来源适用性记录、阻断项与真实审核签署。
- 原子判据修订说明、模拟器/终止合同与独立适用性矩阵。
- 新版正反/边界回答、作者预期单独隔离、分阶段 A/B 包与构建脚本。
- A/B 原始记录、阶段封存摘要、曝光声明、争议与裁定记录；未执行则明确待填。
- 最小适配器、工程边界验证、病例与版本冻结清单。
- 联合试测报告；明确哪些结论来自工程、临床审核、独立评分或真实模型试跑。

验收人按交付证据逐项判断。不得用“系统能运行”替代“题目有效”，也不得用“模型刚好全对/犯错”替代对题目、模拟器和判据的复核。
