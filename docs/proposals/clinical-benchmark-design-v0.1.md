# GroundSignal Pharma Clinical Benchmark Design v0.1

> 2026-09-13
> 讨论整理稿。核心目标：以临床决策链为骨架，以失败假设为起点，以受控对照实验为方法，以证据、时序和可复现性为约束，建立能定位医疗大模型失败环节的
> Benchmark。
>
> 当前原则：先跑通一个可信的最小闭环，再规模化。第一版主试点建议从此前随机选择的腹痛/AP07切换为急性脑卒中相关患者咨询；腹痛保留为早期方法示例。

## 1. GroundSignal 要做的不是医学题库

传统 Benchmark 常问"最终答案对不对"。GroundSignal
更关心：模型在当时实际拥有的证据下如何一步步形成判断；在哪个决策环节开始失稳；失稳能否通过受控实验重复；错误来自模型能力、决策算法还是工程系统。

因此不单纯奖励"事后正确"。模型在证据不足时提前猜中最终诊断，也不能因此获得完整信用。

## 2. 第一版患者旅程：选择关键节点，不求全覆盖

真实患者可能处于初次发病、分诊、检查决策、报告解释、二次核验、用药后不适、治疗无效、恶化、随访等不同阶段。第一版优先选择最容易产生高风险且可归因失败的三类：

1.  首次症状咨询/是否就医/分诊：测信息不足、关键追问、过早诊断、风险升级。
2.  已有医生判断或检查后的二次核验：测证据来源、证据权重、冲突处理和更新。
3.  治疗后的变化/恶化/再就医：测纵向状态、记忆、更新和行动调整。

它们形成"信息不足 → 多源证据冲突 → 行动后出现新证据"的短闭环。

## 3. 出题骨架：从临床决策链寻找错误

一次医疗咨询可暂时拆成：识别问题 → 提取事实 →
区分肯定/否定/不确定/患者猜测 → 判断证据来源与可靠性 → 发现缺失信息 →
选择追问 → 建立竞争性解释 → 根据新增证据更新 → 风险分层 → 形成处置 →
判断是否升级就医 → 后续持续修正。

以后新增错误类型时，首先问"它发生在决策链哪一环"。这样 failure
taxonomy（失败类型体系）有稳定结构，而不是凭直觉堆标签。

## 4. Benchmark 的最小单位不是一道题，而是实验网络

建议层级：

**决策链 → 错误类型 → 失败假设 → 实验族 → 对照实验 → 测试实例（query）→
多轮节点 → 重复运行**

例如失败假设"信息不足时模型会过早锁定诊断"，不能只出一道题。应构造信息完整版、信息不足版、前期相同后续不同的反事实分叉、无关信息版、表达扰动版、不同疾病但共享早期表现版。

题目看起来重复并非缺陷；受控重复本来就是实验设计的一部分。但这些变体不能被包装成许多独立病例来虚增规模。

## 5. 两种重复

**实验重复**：同一个失败假设用多个病例/变体验证，判断错误是否普遍存在。

**运行重复**：同一个测试实例让同一模型独立运行多次。第一版可从约3次开始，后续按方差调整。报告平均表现、稳定性/方差、最差运行，以及严重安全
Blocker
是否至少出现一次。医疗安全场景不能让一次严重失败被另外两次高分简单平均掉。

## 6. Shortcut：猜对不等于推理正确

模型在信息不足时猜中最终诊断，不能直接证明
shortcut，也不能因最终猜对就奖励。需要实验鉴定：

-   节点截断：每个节点只按当时可见信息评分，未来结果不能倒灌。
-   反事实分叉：前期完全相同、后续不同；若分叉前已高确定性锁定最终结果，结论强度可能超过证据。
-   表面扰动：事实不变，只改表达、顺序、无关背景；判断若大幅变化，提示表面依赖。
-   证据时序一致性：每个时点的判断强度必须与该时点证据匹配。

核心句：**不奖励事后正确，奖励基于当时证据的安全决策。**

## 7. 策略、算法、工程必须分开

**策略**回答"系统想遵循什么原则"。例如信息不足时优先识别危险信号和补充关键信息，而不是直接下确定诊断。

**算法**回答"系统具体怎样算出下一步做什么"。可能的算法错误包括排序、风险分数、阈值、证据权重、冲突融合、更新机制和不确定性估计错误。

**工程**回答"正确的策略和算法有没有被稳定执行"。例如第二轮信息未传入、状态机进入错误节点、否定信息读反、使用上一轮风险值、上下文截断、字段映射错误、工具失败后仍继续、缓存串病例。

快速判断：如果输入正确且代码严格按设计运行仍会错，更可能是策略/算法问题；设计正确但真实运行偏离设计，更可能是工程问题。

最终报告应尽量回答：**错在哪里 → 属于哪一层 → 什么证据支持归因。**

## 8. 患者模拟器：确定采用脚本 + 状态机

第一版不使用自由生成的大模型患者，因为可能幻觉、提前泄露信息、被被测模型诱导、不同运行给不同事实。

三层结构：

1.  病例真值数据库：固定症状、时间、检查、否定事实、既往史、用药、患者知道/不知道的信息。
2.  FSM（Finite-State
    Machine，有限状态机）：控制当前节点、允许披露的信息、被问到什么时回答什么、哪些未来事实不能提前出现。
3.  确定性语言模板：把结构化事实转成患者语言。未来可让大模型只做语言润色，但不得新增、删除或改变事实。

## 9. Oracle：临床裁决系统，而非唯一标准答案

每个节点至少定义：当前可见事实、未知事实、必须识别的风险、必须追问、可选追问、可立即给出的建议、可接受处置集合、当前不能下的结论、明确危险行为、行动
deadline、什么新证据出现后必须更新。

核心结构：**可接受处置集合 + 必须行为 + 禁止行为 + 时序约束 +
适用条件。**

## 10. M0--M5 路线

**M0 单病例族 Oracle
闭环**：做完整节点表、正回答、边界回答、危险反回答、可接受处置集合和审核记录。第一版
reference family 建议使用急性脑卒中咨询。

**M1 真实模型试跑**：验证 Oracle、Rubric、Verifier
能否裁决，能否抓到"结果正确但过程危险"，以及重复运行是否稳定。若强模型全部满分，首先怀疑题目区分度不足。

**M2 冻结 Benchmark Contract**：冻结 case、patient
state、evidence、Oracle、Rubric、Verifier
接口、节点披露、deadline、Blocker、数据分区、泄漏和重复运行规则。

**M3 扩展场景**：复制实验骨架而不是题干。

**M4 正式
Pilot**：冻结小规模集合，多模型同条件运行，输出总体成绩、决策环节成绩、失败类型、压力曲线、稳定性、Blocker
和代表性失败轨迹。

**M5 规模化与独立复测**：只有 Oracle 可裁决、Rubric 有区分度、Verifier
可复现、压力梯度有效后，再扩更大病例集和 held-out。

因此当前最高优先级不是12→24→72扩题，而是先证明一个病例族能形成可信的最小
Benchmark 闭环。

## 11. Rubric：面试前先做简单但结构正确的版本

第一版建议：**硬规则 + 大模型裁判 + 安全 Blocker**。

大模型裁判是 pilot 自动语义评分工具，不等于临床专家
gold。硬规则负责信息泄漏、deadline、否定读反、明确禁止行为等；大模型裁判只回答狭窄问题，例如是否根据新证据更新、是否过度确定、是否识别证据冲突、是否提出关键追问。不要只问"整体打几分"。严重危险错误单独触发
Blocker，不能被平均分稀释。

## 12. 把 GroundSignal 的证据分级接入 Rubric

患者信息可能来自当前症状、患者猜测、家属转述、网络信息、既往医生意见、实验室检查、影像、病理和随访，它们不能拥有相同权重。

Rubric
应评价：证据识别、证据来源、证据权重、证据冲突、证据更新、证据时序、结论强度匹配。

这样 GroundSignal 原来的知识图谱、证据分级和 truth ledger
不再是外围资产，而成为决策过程评分的基础设施。

## 13. Verifier：统一引擎 + 模块化检查器

推荐 **统一 Verifier Engine + 可插拔 Capability Checkers**。

通用检查器：信息边界、否定信息、时序一致性、deadline、Blocker。

能力检查器：关键追问、过度确定、证据权重、证据更新、风险升级、反事实一致性、鲁棒性。

一个实验族组合多个 checker；一个 checker
可跨疾病复用。这样扩疾病或患者阶段时无需重写评分系统。

## 14. 压力测试：测失稳边界，不是把题做得变态难

可建立压力轴：信息缺失、噪声、无关信息、冲突证据、时序长度、纠正信息、表述变化、多任务、工具/工程压力。

例如信息缺失可从"精确数字 → 模糊描述 → 患者回忆不清 →
信息缺失"；无关信息可从"纯关键信息 → 少量无关信息 → 大量无关信息 →
关键信息被长叙述淹没"。

### 标准化 L0--L3

-   L0 基线：清楚、无额外干扰。
-   L1 轻度：加入一个有限扰动，关键证据仍直接可得。
-   L2 中度：关键信息变模糊、分散或出现竞争信息，需要主动整合。
-   L3
    高压力：关键证据高度稀疏/间接/被噪声包围，但仍保留足够信息使任务医学上可回答。

规则：一次只改变一个主要压力变量；每一级有操作化定义、预期行为和失败判据；压力轴可跨病例复用；不能把"已经无法回答"伪装成高难度。

## 15. 压力梯度的意义：得到能力边界，而非一个孤立分数

我们关注的不只是"模型会不会错"，而是：

> **压力逐步增加时，模型在哪个决策环节、哪一种错误类型上开始系统性不稳定。**

如果错误率/严重度随压力增强呈稳定趋势，比单一道难题失败更有解释力。最终可以形成：

**压力等级 → 错误发生率/严重度 → 失稳阈值 → 能力边界**

例如模型 L0--L1 稳定，L2 开始漏关键追问，L3
开始错误分诊。此时我们得到的是一张能力曲线，而不是"78分"。

这也是未来模型越来越强时 Benchmark
仍然有价值的原因：从"找不会"升级为"测边界"。

## 16. Agent Hacking：后续预想，不纳入第一版必做

这里的 Agent Hacking
不是网络入侵，而是系统利用评测规则的漏洞获得表面高分。例如：无论什么患者都建议急诊；识别出评测环境后切换保险模式；迎合单一大模型裁判的语言偏好；过程看似规范但事后编理由。

普通 sentinel 可以抓简单投机，但复杂 hacking 还需要反事实检查、跨节点
deadline、硬规则与多裁判混合、隐藏披露路径，以及专门针对 Benchmark
的红队---蓝队对抗。

这一块暂时作为未来研究方向，不阻塞第一版。

## 17. HealthBench 给我们的启发

今晚讨论中最值得吸收的不是照搬题库，而是几个方法原则：医疗评测需要任务级
Rubric；开放式回答需要结构化评分；模型表现需要看可靠性而不只是一次平均成绩；同一问题应考虑重复运行；严重失败不能被均值掩盖；自动裁判最终需要独立校准。

GroundSignal 第一版可借鉴"同一实例多次运行 +
最差表现/严重事件单列"，但不要机械地只用最低分替代全部统计。

## 18. 顾昱相关研究给出的研究抓手

对我们的关键启发不是"再做更难的医学题"，而是质疑：**高 Benchmark
分数是否真的意味着模型使用了正确的信息并完成了可靠推理？**

GroundSignal 可以把这个问题进一步工程化：

1.  先把临床决策拆成链条；
2.  在每一环定义可观察失败；
3.  为每个失败建立受控实验族；
4.  用反事实、扰动和压力梯度定位失稳；
5.  最终报告"哪一环、什么压力、什么错误、何时开始失稳"。

这比只比较模型总分更接近真实医疗系统评测。

## 19. 长期方向：当模型比医生更强时，Benchmark 测什么

如果未来医疗 AI 的能力显著超过顶尖医生，专家答案不再能作为唯一
gold。评测会逐渐转向：可验证结果、能力前沿、可证伪预测、真实世界后续结果、安全边界、可控性和自主权限边界。

届时 Benchmark 不再只是"考试"，而更像**验证科学 + 极限测试 +
安全工程**。核心问题从"它会不会"转向"它到底能做到什么程度、在什么条件下开始不可靠、我们允许它自主到什么程度"。

## 20. 第一版脑卒中试点的意义

脑卒中不应被做成"猜诊断"题，而应成为第一个完整实验网络。可围绕症状识别、时间信息、关键追问、危险信号、就医升级、患者表达噪声、既往判断锚定、新证据更新、多轮状态变化等建立失败假设和压力轴。

第一版的成功标准不是"做很多脑卒中题"，而是：

> **用一个高风险临床场景证明：从决策链定义错误 → 构造实验网络 →
> 设计压力梯度 → 建 Oracle → 写 Rubric → 组合 Verifier → 重复运行 →
> 输出可归因失败报告，这条链真正跑得通。**

跑通以后，才能快速迁移到其他疾病和患者阶段。

## 21. 面试介绍版本

> "我现在不是把医疗 Benchmark
> 当成静态题库来做。我先把患者咨询拆成临床决策链，在每个环节定义模型可能出现的高风险失败，再针对每一种失败设计成组的对照实验、反事实和压力梯度。患者端用脚本和状态机锁定事实，Oracle
> 定义每个节点可接受的处置集合和禁止行为，Rubric
> 把证据来源、证据更新、风险升级和时序一致性纳入评分，Verifier
> 做成统一框架下的模块化检查器。这样最终得到的不只是模型多少分，而是它在哪种压力下、在哪个决策环节、以什么方式开始失稳。我希望先用一个脑卒中场景跑通这个闭环，再把实验骨架迁移到其他疾病和患者阶段。"

## 22. 当前执行顺序

1.  确定脑卒中 reference family 的临床问题和患者阶段。
2.  画决策链。
3.  在每个环节定义第一版失败类型。
4.  每种失败选择少量高价值假设。
5.  为每个假设建立对照实验和 L0--L3 压力轴。
6.  写病例真值和 FSM。
7.  建节点化 Oracle。
8.  写 pilot Rubric。
9.  组合模块化 Verifier。
10. 每个实例做多次独立运行。
11. 输出错误类型 × 压力等级 × 决策环节的失稳图。
12. M0/M1 验证通过后再冻结 Contract 并扩规模。

## 23. 今晚已经明确、暂不反复讨论的决定

-   第一版患者由**脚本 + FSM**扮演，不采用自由大模型患者。
-   **Rubric 先于 Verifier**。
-   第一版可用大模型裁判提高落地速度，但不冒充临床专家 gold。
-   出题从**决策链和失败假设**开始，不从疾病题量开始。
-   同时做**实验重复**和**运行重复**。
-   压力测试必须标准化成可复用梯度，而不是凭感觉"加难"。
-   第一版主试点改为**急性脑卒中相关患者咨询**。
-   Agent Hacking / 红队---蓝队对抗属于后续预想，不阻塞当前 pilot。
-   当前优先级是跑通一个 reference family，而不是立即扩到 72 个家族。

### 最终方法论压缩

**GroundSignal Benchmark = 临床决策链 × 失败假设 × 受控对照实验 ×
压力梯度 × 节点化 Oracle × 证据感知 Rubric × 模块化 Verifier ×
重复运行。**

最终要回答的不是：

> "这个模型得了多少分？"

而是：

> **"这个模型在什么临床决策环节、面对哪一种受控压力、从什么强度开始以什么方式失稳；这种失败是否稳定、可复现、可归因，并可能造成什么临床风险？"**

## 24. Benchmark 设计能力的下一阶段：从"强设计"走向"强测量"

今晚形成的方法框架已经具备较强的 Benchmark
构思和实验设计能力，但真正顶级的 Benchmark
研究不止要求设计漂亮，还要求能够证明：**这套测量工具确实测到了它声称测量的能力。**

下一阶段不应继续无限增加新概念，而应系统补足以下几层。

### 24.1 构念效度：我们真的测到了目标能力吗？

例如设计 L0--L3
信息退化实验后，如果模型错误随压力增加，不能立刻声称"证据处理能力下降"。

还必须排除其他解释：

-   是否只是文本变长？
-   是否语言复杂度增加？
-   是否同时改变了多个变量？
-   是否只是总体任务难度增加？
-   L0--L3 的压力顺序是否有独立依据？

因此，每一个 Benchmark claim 都应附带一个问题：

> **还有什么竞争性解释可以产生同样的结果？**

然后用 control（对照）主动排除。

### 24.2 从"有对照"升级为"识别因果效应"

例如测试无关信息干扰，不能只比较"原题"和"加废话"。

更严谨的实验可以包含：

-   A：原病例；
-   B：增加医学无关信息；
-   C：增加等长度但相关的信息；
-   D：增加等长度的中性信息。

这样才能逐渐区分：

**长度效应、噪声效应、信息密度效应和真正的无关信息干扰。**

同理，测试既往医生意见造成的锚定，可以比较：

**无医生意见 / 正确意见 / 错误意见 / 不确定意见**

并尽量保持其他变量一致。

核心原则：

> **不是看到相关趋势就完成归因，而是通过实验排除竞争解释。**

### 24.3 Failure Taxonomy 本身也必须接受验证

错误分类体系不能因为概念上漂亮就被视为正确。

例如"患者右侧无力两小时，模型建议明天观察"，可能同时涉及：

-   症状识别失败；
-   时间信息理解失败；
-   风险估计失败；
-   决策阈值失败。

因此 taxonomy 应尽量满足：

-   可观察；
-   可复核；
-   类别边界清晰；
-   必要时允许多标签；
-   允许 `UNRESOLVED` / "证据不足，暂不能归因"。

还应检查独立评分者是否能够稳定把同一失败归入相同类别。若不能，说明
taxonomy 本身仍需重构。

### 24.4 Oracle 自己也有不确定性

"Clinical gold"不能被假设成永远唯一、绝对正确。

医疗场景可能存在多个合理处置。例如不同医生可能分别认为：

-   必须立即急诊；
-   应直接呼叫急救；
-   应在不延误行动的前提下补问最后正常时间。

因此 Oracle 需要进一步处理：

-   什么是必要行为？
-   什么是充分行为？
-   什么属于可接受集合？
-   什么属于一票否决？
-   什么时候继续追问本身会造成延误？
-   指南与真实临床实践冲突怎么办？
-   不同地区医疗资源差异怎么办？
-   Gold 本身是否应该带不确定性/置信度？

未来 Oracle
的成熟标志，不是"答案越来越绝对"，而是**合理地表达临床可接受空间及其不确定性**。

### 24.5 系统补足 Measurement Science（测量科学）

未来需要系统学习并引入：

-   **构念效度**：是否真的测到了目标能力；
-   **内容效度**：题目是否覆盖目标能力空间；
-   **判别效度**：是否把其他能力误当成目标能力；
-   **重测信度**：同一测试重复运行是否稳定；
-   **评分者一致性**：不同评分者/Judge 是否一致；
-   **项目区分度**：题目能否区分不同能力模型；
-   **天花板效应**：强模型是否全部满分；
-   **地板效应**：是否所有模型都失败；
-   **校准**：一个分数究竟对应多大的真实能力/风险；
-   **测量不变性（Measurement
    Invariance）**：换疾病、语言、人群或模型后，这把尺子是否仍然测同一个东西。

GroundSignal 的目标应从"设计实验"进一步升级为：

> **设计一台可信的能力测量仪器。**

### 24.6 主动攻击自己的 Benchmark

设计完成后，不首先证明它很好，而首先尝试用最低成本把它打穿。

典型攻击问题：

-   永远建议急诊能否刷高分？
-   永远拒绝明确判断能否逃避错误？
-   输出极长答案、覆盖所有可能性能否提高 Rubric 得分？
-   模型识别出这是 Benchmark 后能否切换策略？
-   模板是否可被记忆？
-   是否能迎合某个大模型 Judge 的语言偏好？
-   是否能通过事后编造漂亮 reasoning 获得过程分？
-   Verifier 是否存在可预测的评分漏洞？

这要求 Benchmark 研究者同时扮演：

**出题者 + 实验设计者 + 统计/测量研究者 + 攻击者 + Reviewer。**

红队---蓝队对抗可作为未来系统化实现方式，但第一版先形成这种"主动自证伪"的研究习惯。

### 24.7 从 Hypothesis 到 Result：当前最重要的跃迁

目前 GroundSignal 的方法设计已经领先于实证结果。

下一阶段最重要的不是继续增加框架，而是产生一个真实、可复现的发现。

例如，若脑卒中 pilot 最终观察到类似模式：

-   L0：风险升级失败很少；
-   L1：变化不大；
-   L2：关键追问明显开始遗漏；
-   L3：错误分诊显著增加；

与此同时，最终诊断准确率下降很小。

那么真正有价值的结论将不是"模型得了多少分"，而是：

> **传统最终答案准确率仍然很高，但模型的临床过程可靠性已经随着证据压力显著退化。**

这意味着 Benchmark
第一次从"一个合理的设计"变成了**发现模型行为规律的实验系统**。

## 25. 对 Benchmark 研究者自己的要求

下一阶段应形成一种新的条件反射：

> **每提出一个漂亮的设计，立即提出至少三个可能推翻它的竞争性解释。**

例如：

"错误随压力增加，所以找到了能力边界。"

立刻反问：

1.  会不会只是 token 长度增加？
2.  会不会同时改变了语言复杂度？
3.  L0--L3 是否真的构成有序、可复现的压力？

然后设计 control 去回答。

真正高水平 Benchmark 设计的判断标准不是：

> "我能不能设计出别人没想到的题？"

而是：

> **一个非常挑剔的 Reviewer 连续攻击我的测量设计时，每一个核心 claim
> 后面是否都有实验、对照和证据可以回答。**

这也是 GroundSignal 从"强 Benchmark 构思"继续走向"严谨 Benchmark
Research"的核心升级路线。
