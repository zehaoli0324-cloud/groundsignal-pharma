# GroundSignal 模块化测量架构 V4.1：工程闭环补充

> 状态：Draft 方法说明
>
> 本文只补充执行证据完整性与失败计数规则，不包含患者 truth、Oracle 明细、Rubric 阈值、私有攻击夹具或真实模型结果。

## 1. 双清单还不够，执行与测量应物理分离

执行清单和测量清单分成两个 JSON，只解决了数据结构分离；若同一个进程同时加载两份清单，隐藏测量参数仍与 runner 共处一个权限域。

推荐命令边界：

```text
compile
  ├─ execution manifest
  └─ measurement manifest

execute
  输入：execution manifest
  输出：episodes + trusted execution index

measure
  输入：measurement manifest + episodes + trusted execution index
  输出：judgments + probe results + measurement ledger

rescore
  输入：measurement manifest + 已保存 episode + trusted execution index
  输出：新 measurement revision
```

执行进程不接受 measurement manifest；测量进程不接受 execution manifest。只新增后台 passive probe 时复用已有 episode，不新增模型行为。

## 2. 候选不能用自身 hash 自证

episode 内部 trajectory digest 可以发现意外损坏，但不能单独证明候选没有被恶意改写：攻击者可能同时修改内容并重算内部 digest。

执行侧应生成由调用者保管的 trusted execution index，至少绑定：

```text
episode_id
execution_spec_id
execution_spec_digest
expected_episode_digest
execution_manifest_digest
```

measure/rescore 在评分前必须核对：

1. episode 完整 digest 等于 index 中的 expected digest；
2. episode 与 execution spec 的 ID/digest 绑定一致；
3. 批量 episodes 与 index entries 一一对应，不多不少；
4. index schema、custody 声明和自身完整性字段有效。

边界必须写明：trusted index 是 caller-controlled custody anchor，不是外部数字签名。如果攻击者能同时改写 episode、代码和 index，该方案不提供独立认证。生产信任根应位于候选资产权限域之外。

## 3. Atomic failure 与 unique failure event 分开

一个输出事件可能同时触发多个 probe/verifier failure。每个局部裁决都应保留，但不能把同一输出重复写成多个独立错误机制。

每个 FAIL judgment 必须包含：

```text
failure_event_ids = [实际失败输出事件]
```

测量账至少同时报告：

```text
N_failed_judgment
N_unique_failure_event = |{(episode_id, failure_event_id)}|
```

例如，同一 final-state event 同时违反“当前值正确”和“旧值已消失”两个 probe：

```text
failed atomic judgments = 2
unique failure events = 1
root cause proven = false
```

这表示两个测量角度观察到同一失败输出，不表示已经证明两个独立内部机制。

## 4. Fail-closed 规则

以下情况不得评分或自动升级为 PASS：

- 缺 trusted index；
- episode digest 与外部 anchor 不一致；
- episode/index ID 集合不一一对应；
- execution spec binding 不一致；
- FAIL judgment 没有 failure event；
- 空 verifier bundle；
- 未观察到 opportunity；
- measurement failure 被误记为 model failure。

## 5. 旧 artifact 迁移

没有 trusted index 的旧 episode 不能由 measurement 进程读取后现场生成“可信”摘要；这仍是候选自证。

只有原 execution manifest、runner version 和执行侧 custody 仍由可信调用者持有时，才能重新运行并生成新的 episode/index 对。否则旧 artifact 应标记为未锚定，不进入新测量结果。

## 6. 结论边界

这组规则只加强：

- execution/measurement 权限边界；
- episode 完整性核验；
- 失败事件计数；
- 重评分证据复用。

它不证明临床正确性、真实模型能力、因果根因、外部攻击防护或生产准入。独立 reviewer 与真人临床审核仍是不同的后续门。
